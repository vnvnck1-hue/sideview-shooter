# 단말기 시스템 컨셉 (Terminal System)

*작성 2026-09-19 · 대상 `GodotPrototype/`*

스테이션 곳곳의 **단말기(Terminal)** 에 접속해 CRT 화면 UI 로 들어가고, 거기서
기록을 읽거나 전력을 재분배하거나 **다른 방의 센트리건을 원격 조종**하는 시스템.
《Alien: Isolation》 의 단말기 · 리와이어 · 보안 관제 흐름을 레퍼런스로 삼는다.

핵심 감각은 **"플레이어의 몸은 여기 있고, 시선만 스테이션 저편으로 건너간다"** 이다.
그래서 접속 중에는 플레이어가 움직이지 못하고, 원격으로 보고 있는 방에서 벌어지는
일에 몸으로 개입할 수 없다. 이 무력감이 이 시스템의 긴장이다.

---

## 1. 역할 분리 (5종)

단말기는 하나의 만능 기계가 아니라 **역할이 다른 다섯 종류의 기계**다.
역할마다 외형 자산 · 화면 발광색 · CRT 프리셋 · 할 수 있는 일이 다르다.

| 역할 id | 이름 | 자산 | 화면 색 | CRT 프리셋 | 하는 일 |
|---|---|---|---|---|---|
| `link` | 세바스토링크 단말기 | `industrial_access_terminal_v4` | 청록 | `green` | 음성 로그 · 메일 열람, 문/환기구 개방 |
| `security` | 보안 관제 단말기 | `industrial_access_terminal_v1` | 호박 | `green` | **방어 그리드 — 센트리건 원격 접속** |
| `rewire` | 리와이어 배전반 | `terminal_wall_access_v1` (벽걸이) | 붉은 | `amber` | 제한 전력 재분배 (정화·조명·카메라·잠금) |
| `save` | 비상 저장 단말기 | `industrial_access_terminal_v3` | 흰-청 | `amber` | 출입 카드를 꽂아 게임 저장 |
| `survey` | 구역 현황 단말기 | `terminal_floor_console_v1` (낮은 콘솔) | 녹 | `green` | **구역 지도 — 스테이션 개략도 판독** · 센서 기록 |

> 센트리 조종은 지시대로 **`green`(녹색 단색 형광, P1) 프리셋** 을 쓴다.
> `rewire`/`save` 만 `amber` 로 두어 "전기 계통 기계" 라는 결을 따로 준다.

위 자산·설치 방식은 역할의 **기본값**이고, 단말기 정의가 `tex`/`wall` 로 덮어쓸 수 있다.
자리가 좁은 방(복도·침실)에서는 같은 역할이 벽걸이 패널로 달린다 — §4 참고.

> 지도는 `security` 의 방어 그리드 화면이기도 하다 — 포탑을 목록이 아니라 **지도 위에서** 고른다.
> 지도의 레이아웃 산출·판독 등급·배치 근거는 `Docs/STATION_MAP.md`.

### 접근 권한 (grid)

`grid` 는 역할에 따라 뜻이 갈린다 — `security` 는 **잡을 수 있는 포탑의 범위**,
`survey` 는 **지도에서 실시간으로 읽히는 범위**다. 관할 밖은 다녀온 방만 과거 기록으로 뜬다.

`security` 단말기는 **자기 관할 구역의 센트리건만** 잡을 수 있다.
관할은 단말기 정의의 `grid` 에 구역 이름 또는 방 id 목록으로 적는다.
관할 밖 포탑은 목록에 `■ 권한 없음` 으로 회색 표시되어 **있다는 것은 보이되 잡히지 않는다** —
"저 방에 포탑이 있는데 여기선 못 잡는다" 가 다음 단말기를 찾게 만드는 동기가 된다.

## 2. 접속 플로우

```
[방 안]  단말기 옆 → W/↑
   │
   ├─ ① 카메라 밀어넣기 (0.45s)  zoom 0.5→0.86, 화면 중심이 단말기 스크린으로
   ├─ ② 화면 플래시 + CRT 프리셋 교체 (사용자 프리셋은 스택에 밀어 두고 복구)
   ├─ ③ CRT 전원 인가: 가로 한 줄 → 세로로 펼쳐짐 (collapse 1→0)
   └─ ④ 부팅 텍스트 타이핑 → 루트 메뉴
        │
        ├─ [로그]     목록 → 본문 (한 글자씩 타이핑)
        ├─ [배전]     회로 4개 · 총 전력 3 유닛을 나눠 켬
        ├─ [저장]     카드 삽입 연출 → 저장
        ├─ [구역 지도]  스테이션 개략도 (survey) — 방 위를 커서로 훑으며 판독
        └─ [방어 그리드]  **같은 지도** 위의 센트리건 (security) — 관할 포탑에만 커서가 선다
              │  선택 → "LINKING…" 채널 전환 글리치 (desync + noise 스파이크, 0.57s)
              ▼
        [원격 조종]  월드가 그 방으로 교체됨 · 플레이어는 숨고 카메라는 포탑에 고정
                     포탑이 자동 전개되어 조종 상태로 넘어옴 (마우스 조준 · 좌클릭 사격)
                     화면 위에 얇은 녹색 프레임 HUD (호출부호 · 방 이름 · 총열 과열)
              │  ESC / W → 역글리치 → 방어 그리드 목록으로 복귀
              ▼
        ESC → CRT 전원 차단 (collapse 0→1, 가로 한 줄로 수축 + 플래시)
              → 카메라 후퇴 → 플레이어 조작 복귀
```

### 전환 연출 목록

접속의 몰입은 **"장면이 바뀐다" 가 아니라 "신호가 바뀐다"** 로 표현한다.
전부 `crt.gdshader` 에 추가한 세 유니폼으로 만든다.

| 유니폼 | 뜻 | 쓰이는 곳 |
|---|---|---|
| `collapse` | 0=정상, 1=가로 한 줄로 수축 (+가로로 늘어나며 밝아짐) | 전원 인가/차단 |
| `flash` | 화면 전체 가산 백색 | 전원 순간, 채널 전환 순간 |
| `desync` | 주사선 행이 가로로 찢겨 흔들림 | 채널 전환(LINKING), 링크 불안정 |

- **전원 인가** — `flash` 0→1→0 (0.08s) 과 함께 `collapse` 1→0 (0.34s, ease out).
- **전원 차단** — `collapse` 0→1 (0.26s, ease in) + 마지막에 `flash` 짧은 스파이크.
- **채널 전환** — `desync` 0→1 (0.12s) 유지 0.2s 동안 월드 방 교체 → `desync` →0 (0.25s),
  동시에 `noise` 를 0.22 까지 밀었다가 프리셋 값으로 되돌린다. 방 교체는 글리치의 33% 지점에서 일어난다.
- **부팅 타이핑** — 줄마다 0.055s(10줄 ≈ 0.55s) + 0.35s 뜸, 커서 `_` 는 0.5s 주기 점멸.
  카메라가 62% 밀려 들어갔을 때 화면이 켜진다 — 먼저 켜면 "다가가는" 느낌이 사라진다.
- **카메라** — 단말기 스크린 지점으로 `zoom`/`position` 을 동시에 `TRANS_CUBIC/EASE_OUT` 보간.

## 3. 원격 조종의 규칙

원격 조종은 **월드 자체를 그 방으로 바꾼다** (별도 뷰포트에 두 방을 동시에 그리지 않는다).
1600×900 SubViewport 하나를 그대로 쓰므로 조명·파티클·셰이더가 실제 플레이와 100% 같다.

- 플레이어 노드는 **숨고**(`visible=false`) 입력이 꺼진 채 **포탑 위치로 옮겨진다**.
  몬스터는 플레이어를 쫓으므로 자연히 포탑으로 몰려온다 — 이게 원격 포탑전의 구도다.
- 원격 중 플레이어 피격은 **넉백 없이 화면 흔들림·색수차만** 준다
  (몸은 다른 방에 있다. 맞는 것은 포탑이다).
- 링크를 끊으면 원래 방 · 원래 위치 · 원래 시선으로 복귀한다. 포탑은 무인 대기로 남는다.
- 방을 떠나거나 F1 로비로 나가면 링크는 강제로 끊긴다.

### 왜 이 방식인가

| 안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| A. 두 번째 SubViewport 에 원격 방을 렌더 | 단말기 화면 안에 작게 보임 (아이솔레이션 CCTV 에 가장 가까움) | 방 하나를 통째로 이중 조립 · 조명 2배 · 프로토 단계에 과함 | 보류 |
| **B. 월드를 원격 방으로 교체** | 연출·조명·손맛이 본편과 동일 · 비용 0 | 단말기 화면 "안" 이 아니라 화면이 시야를 채움 | **채택** |

B 는 "화면에 얼굴을 붙인 1인칭 관제" 로 읽힌다. 녹색 CRT 가 전 화면을 덮으므로
이게 **직접 보는 장면이 아니라 중계된 화면** 이라는 사실이 계속 남는다.

### 배치 규칙 (겪은 것)

- **`security` 는 바닥에 480×507px 가 필요하다.** 맵 21개 방 중 그만한 빈 바닥이 남은 곳은 작업실뿐이었다.
  그래서 단말기 정의에 `tex`/`wall` **덮어쓰기**를 두어, 좁은 방에서는 같은 역할을 벽걸이 패널
  (`terminal_wall_access_v1`, 340×166)로 단다. 설치 방식 판정은 `TerminalData.is_wall()` 한 곳에만 둔다 —
  방 배치(`Room`)와 그리기(`AccessTerminal`)가 서로 다른 답을 내면 프랍이 바닥에 박힌다(실제로 한 번 그랬다).
- 벽걸이는 **정면문(바닥선−306px)** 윗변을 피해 `fy` 를 잡는다. 천장이 낮은 복도(4행 = 462px)에서는
  `fy` 를 너무 올리면 천장을 뚫는다.
- 바닥형은 그 자리 **천장 높이**를 넘으면 안 된다 — `validate_map.gd` 가 이제 이것도 검사한다.
- 정면문 앞·측벽문 자리는 비운다. 단말기 앞 좌우 150px(`INTERACT_RANGE`)도 비우는 것이 좋다.
- 배치 후보에서 **대형 정비 홀·전력 릴레이실의 방어포는 뺐다** — 정면문 앞을 가리거나 376px 빈 바닥이 없었다.
  전력 구역 방어포는 바닥이 통째로 빈 **케이블 덕트**로 옮겼다.

## 7. 남은 것 / 확장 여지

- 오디오 로그의 **소리** (현재는 타이핑되는 텍스트만).
- 지도의 **판독 시각**(방마다 "언제 읽었는지")과 `rewire` 의 카메라 회로 연동 — `Docs/STATION_MAP.md` §7.
- `rewire` 배전 결과를 실제 방 상태에 반영 (조명 소등 · 카메라 정지 · 문 잠금 해제).
  지금은 화면 안에서만 토글되고 월드에 영향을 주지 않는다.
- `save` 는 연출만 — 실제 세이브 데이터는 아직 없다.

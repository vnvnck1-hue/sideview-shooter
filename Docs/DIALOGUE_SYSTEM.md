# NPC · 대화 시스템

> 2026-09-19. 단말기 시스템(`Docs/TERMINAL_SYSTEM_CONCEPT.md`)과 같은 규칙으로 만든 두 번째 상호작용 계통.
> 인물 규격은 `Docs/CHARACTER_ART_GUIDE.md`, 이야기 근거는 `AI_Robot_Base_Narrative_Design_Notes.md`.

## 1. 한 줄 요약

플레이어(로봇)가 생존자 옆에서 **W/↑** 를 누르면 카메라가 두 사람 사이로 밀려 들어가고,
글자가 **한 자씩 찍히는** 대사가 뜬다. 선택한 대답은 플래그로 남아 **다른 인물의 다음 대화**를 바꾼다.

**대사를 어떤 모양으로 띄울지는 아직 고르는 중이다.** 타자 엔진 하나에 표시 방식 다섯 가지를 얹어 두었고
(§3-1), 로비의 **대화 UI 랩**에서 같은 대사를 방식만 바꿔 가며 나란히 본다.

## 2. 파일 나눔 — 무엇이 어디를 맡는가

| 파일 | 맡는 것 |
|---|---|
| `GodotPrototype/scripts/npc_data.gd` | **내용** — 등장 인물 표(CAST) · 대사 나무(LINES) · 플래그 뜻(FLAGS) |
| `GodotPrototype/scripts/npc_state.gd` | **기억** — 플래그 저장소(static). 방을 옮겨도 남고, 로비로 나가면 지워진다 |
| `GodotPrototype/scripts/npc.gd` | **몸** — 서 있기 · 숨쉬기 · 돌아보기 · 끄덕이기 · 말걸기 표식 |
| `GodotPrototype/scripts/dialogue_runtime.gd` | **나무 걷기** — 노드 → 선택지 → 다음 노드, 플래그 세우기 |
| `GodotPrototype/scripts/dialogue_bubble.gd` | **연출** — 한 자씩 찍히는 글자 · 태그 · 선택지 + **표시 방식 표(STYLES)** |
| `GodotPrototype/scripts/dialogue_lab.gd` | **비교** — 표시 방식 5종을 실제 화면에서 바꿔 보는 랩 (scenes/DialogueLab.tscn) |
| `GodotPrototype/scripts/main.gd` | **바깥** — 조작 잠그기 · HUD 감추기 · 카메라를 말하는 사람 쪽으로 |
| `GodotPrototype/scripts/room_data.gd` | **배치** — `{"type": "npc", "id", "x", "facing"}` |

배치와 내용이 갈라져 있는 것은 단말기와 같은 이유다. 맵을 옮겨도 대사 파일을 건드리지 않고,
대사를 고쳐도 맵 파일을 건드리지 않는다.

## 3. 연출

말풍선은 **말하는 사람 머리 위 월드 좌표**에 꼬리를 붙인 패널이다.
(창 좌표로 그려 글자는 또렷하고 크기가 일정하되, 꼬리는 매 프레임 상대의 머리를 다시 가리킨다.)

### 모양 — 아직 고르는 중 (§3-1)

처음에는 카타나 제로 그대로 밝은 크림색 둥근 말풍선으로 만들었다가 화면 톤과 겉돌아,
**만화 말풍선이 아니라 HUD 패널**로 바꿨다 — 거의 검은 청회색 판, 모서리를 깎은 팔각형,
인물 강조색 테두리 한 겹, 위쪽 한 단 밝은 립, 삼각 꼬리, 상단에 꽂힌 이름표.
그 뒤 **다른 갈래도 같이 보려고** 표시 방식을 표로 빼서 실행 중에 바꿀 수 있게 했다.

### 글자 — 타자는 가져오고 흔들림은 덜어내고

1. **한 자씩 찍힌다.** 찍히는 순간 아래에서 5px 올라오며 밝아진다 (`POP_TIME` 0.11초). 흩어지지는 않는다.
2. **찍힌 글자는 가만히 있는다.** 모든 글자를 상시로 떨게 했더니 읽기가 힘들었다. 이제 움직이는 글자는
   `[shake]` · `[wave]` 로 **직접 지정한 구간뿐**이고, 그래서 그 구간이 진짜로 눈에 띈다.
   다 찍힌 뒤 움직일 것이 없는 줄은 아예 다시 그리지 않는다(`_has_motion`).
3. **문장부호 뒤에 저절로 쉰다.** `…` 가 가장 길고 `,` 가 가장 짧다.
4. **말투가 인물마다 다르다.** `VOICES` 가 타자 속도를 정한다 — 델 박사는 느리고(27), 유나는 빠르다(44).
5. **패널은 글 전체 크기로 먼저 잡고** 열린다. 글이 늘어나며 커지지 않는다.
6. **확인 키를 미리 누르면** 남은 글자가 한꺼번에 앉는다. 한 번 더 누르면 다음 줄.

### 대사 태그

| 태그 | 쓰임 |
|---|---|
| `[shake]…[/shake]` | 떤다 — **한 대화에 한두 번만** |
| `[wave]…[/wave]` | 물결친다 — 비꼼 · 힘 빠짐 |
| `[c=#rrggbb]…[/c]` | 글자색 — 사람 이름, 결정적인 낱말 |
| `[p=0.4]` | 그 자리에서 0.4초 쉰다 |
| `[s=0.7]…[/s]` | 그 구간 타자 속도 배율 (작을수록 느리다) |

굵게 · 기울임은 쓰지 않는다. **강조 예산**: 대사 전체를 통틀어 `[shake]` 2곳, `[wave]` 2곳,
`[c=]` 4곳뿐이다. 이 예산을 늘리는 순간 강조는 강조가 아니게 된다.
대부분의 호흡은 `[p=]` 쉼만으로 만든다.

## 3-1. 표시 방식 — 다섯 갈래 (`DialogueBubble.STYLES`)

**타자 엔진은 하나**다. 글자를 한 자씩 찍고, 태그를 풀고, 줄을 접는 코드는 방식이 달라도 같은 것을 쓴다.
방식이 정하는 것은 **어디에 놓고 · 어떤 판 위에 그리고 · 이름을 어떻게 보여 주고 · 선택지를 어떻게 세우는가** 뿐이다.

| # | 방식 | 어디에 | 결 | 대가 |
|---|---|---|---|---|
| 1 | **카타나 제로** | 말하는 사람 머리 위 + 꼬리 | 화면을 안 가리고, 누가 말하는지가 **위치로** 읽힌다 | 대사가 길면 판이 화면을 덮고, 인물이 화면 끝에 있으면 꼬리가 어색해진다 |
| 2 | **비주얼 노벨** | 화면 하단 전폭 띠 + 이름표 | 긴 대사에 자리가 넉넉하고 눈이 한곳에 고정된다 | 화면 아래를 계속 덮는다. 누가 말하는지는 이름표로만 |
| 3 | **자막** | 하단, 상자 없음 | 화면을 가장 적게 가린다. 영화적 | 어두운 배경에서 읽기가 가장 약하다(글자 그림자로 버틴다) |
| 4 | **누적 로그** | 오른쪽 아래, 지난 줄이 위로 쌓임 | 흐름을 놓치지 않는다. 선택지에 번호가 붙어 숫자 키로 바로 고른다 | 시선이 인물에서 떠나 화면 오른쪽에 머문다 |
| 5 | **레트로 박스** | 가운데 아래, 흰 테두리 + 고정폭 글꼴 | 고전 RPG 의 결. 읽기 가장 또렷하다 | 이 게임의 HUD 결과 가장 멀다 |

표의 한 줄이 곧 코드의 한 항목이다:

```gdscript
{
    "id": "katana", "name": "카타나 제로", "desc": "…",
    "place": "head",        # head(머리 위) · bottom(하단 가운데) · side(오른쪽 아래)
    "panel": "hud",         # hud · band(하단 띠) · none(상자 없음) · retro · log
    "tail": true,           # 꼬리로 말하는 사람을 가리키는가
    "name_mode": "plate",   # plate(꽂힌 이름표) · inline(대사 앞에 붙여 같이 찍는다) · none
    "choices": "rows",      # rows(캐럿) · numbered(1. 2. 3. — 숫자 키로 바로)
    "log": 0,               # 위에 남겨 두는 지난 줄 수
    "mono": false, "width": 700.0, "fixed": false, "lines": 0,
}
```

고른 값은 `static var style_index` 라 **씬을 다시 로드해도 남는다**
(GameCamera.PRESETS · DepthPreset.PRESETS 와 같은 방식). 환경 변수 `DIALOGUE_STYLE=<0..4>` 로 시작값을 고정할 수 있다.

### 대화 UI 랩 (`scenes/DialogueLab.tscn`)

로비의 **"대화 UI 랩"** 버튼. 실제 방·조명·인물 위에서 돌아간다 — 결국 "이 게임 화면에서 어떻게 보이나" 가
답이므로 빈 씬이 아니라 진짜 게임 화면을 쓴다(근경 랩과 같은 생각).

| 키 | 하는 일 |
|---|---|
| `1`~`5` | 표시 방식 직접 고르기 |
| `Tab` / `F7` | 다음 방식 |
| `[` `]` | 말 거는 상대 바꾸기 (그 인물이 있는 방으로 바로 옮겨 간다) |
| `R` | 지금 대화를 처음부터 다시 |
| `0` | 인과관계 플래그 초기화 (첫 만남 대사로) |

방식을 바꾸면 보고 있던 줄을 **처음부터 다시 찍는다** — 비교할 때는 타자 연출까지 봐야 하므로.
게임 안에서도 `F7` 로 순환할 수 있다(다음 대사부터 적용).

## 4. 카메라

대화 줌은 고정값이 아니라 **두 사람 사이 거리**에서 나온다.

```
화면에 담을 폭 = |NPC.x − 플레이어.x| + DIALOGUE_FRAME(816)
줌            = 1600 / 그 폭        (0.78 ~ 1.25 로 자른다)
```

나란히 선 두 사람이 늘 비슷한 크기로 잡힌다. 잡는 **지점**은 두 사람 가운데에서
말하는 쪽으로 `DIALOGUE_BIAS`(0.42)만큼 치우친다 — 둘 다 화면에 남으면서
"지금 누가 말하는가" 가 구도로도 읽힌다. 화자가 바뀔 때만 옮기고(`DIALOGUE_PAN` 0.40초),
매 줄 출렁이지는 않는다.

> 이 과정에서 `GameCamera` 의 버그를 하나 고쳤다. `focus_at()` 으로 잡아 둔 지점이
> **화면보다 좁은 방에서는 무시되고** 방 가운데에 붙잡혔다. 이제 고정 지점이 좁은 방 규칙보다 앞선다.
> 단말기 접속(zoom 0.86)도 좁은 방에서 같은 증상이 있었고 함께 나았다.

화면보다 좁은 방에서는 두 사람이 어차피 다 보이는데도 화자 쪽으로 밀면 **방 밖 어둠만 더 드러난다.**
그래서 잡는 지점의 x 를 `(방 폭 + 여백×2 − 보이는 폭) / 2` 만큼만 방 가운데에서 벗어나게 자른다 —
에어록처럼 작은 방에서는 편향이 0 이 되어 방이 화면 가운데에 그대로 머문다.

## 5. 대사 나무

`LINES[<npc id>]` 는 노드 사전이다. 노드 하나 = 말풍선 하나.

```gdscript
"shutter2": {
    "text": "격벽은 무게로 떨어진 게 아니야. [p=0.4]누군가 [shake]손으로[/shake] 내렸다.",
    "set": ["lockdown"],          # 이 줄이 뜨는 순간 세워지는 플래그
    "next": "shutter3",
},
```

| 키 | 뜻 |
|---|---|
| `who` | 말하는 사람 (생략 = 그 NPC, `"player"` = 로봇) |
| `text` | 대사 (태그 포함) |
| `set` | 이 줄에서 세우는 플래그 |
| `branch` | `[[조건, 노드], …]` — `next` 보다 먼저, 조건이 맞는 첫 줄로 |
| `next` | 다음 노드 (없으면 대화 종료) |
| `choices` | `[{text, to, if, set}]` — 줄이 다 찍힌 뒤 뜬다 |

`entry` 는 **말을 걸 때마다** 위에서부터 평가해 첫 번째로 맞는 노드에서 시작한다.
그래서 같은 인물이 상황에 따라 다른 말로 맞이한다.

조건식은 일부러 아주 좁다 (`NpcState.test`): `""`(항상) · `"flag"` · `"!flag"` ·
`"a & !b"` · `"seen:npc/node"`(그 줄을 본 적이 있다).

같은 문장을 조건만 달리해 두 번 적는 것은 **의도된 수단**이다 —
말은 똑같지만 대가가 다른 선택을 표현한다:

```gdscript
{"text": "관제원이 방어 그리드로 돌렸다.", "to": "told", "if": "!promised", "set": ["told_keeper", "keeper_bitter"]},
{"text": "관제원이 방어 그리드로 돌렸다.", "to": "told", "if": "promised",  "set": ["told_keeper", "keeper_bitter", "broke_promise"]},
```

## 5-1. 말투 — 사람은 사람처럼, 기계만 기계처럼

대사를 쓸 때 지키는 규칙은 하나다. **아무도 명언을 하지 않는다.**

- 말은 **끊긴다.** "…어. 진짜 걸어 들어오네." / "…아. 그랬구나."
- 완결된 문장을 고집하지 않는다. 한 단어짜리 대사가 가장 세게 박힌다 — "…세린이." / "…유나가."
- 되묻고, 반복하고, 스스로 말을 취소한다. "미안. 나 요즘 문소리만 나면 심장이… 아니다. 됐어."
- 감정은 설명하지 않고 **문장 모양으로 새어 나오게** 한다.
  세린이 궁지에 몰리면 문장이 짧아지고("그래, 내가 내렸어."), 미나는 화내는 대신 조용해진다("…아.").
- 비유는 **그 사람이 실제로 다루는 것**에서만 나온다. 미나는 펌프와 수조, 아르카디는 문.
  그것도 어쩌다 한 번이고, 비유를 하려고 말을 꺼내지는 않는다.
- **잠언은 인물당 최대 하나**, 그것도 진짜로 무게가 실리는 자리에서만.
  지금은 두 곳뿐이다 — 아르카디의 "문은 누가 지켜야 하잖냐", 델 박사의 "나한텐 그걸 고칠 권한이 없어."

> **한 번 실패한 방향** (2026-09-19): 베르나르 베르베르식으로 써 봤더니 다섯 명이 전부
> 잠언 제조기가 됐다. 짧은 평서문 · 숫자 · 비유 · 격언조 마무리라는 **형식만** 흉내 내니
> 구어가 아니라 낭독이 되고, 감정이 전혀 안 읽혔다. 형식은 버리고
> **관찰자적 거리감과 아이러니**만 남겼다 — 그것도 인물이 아니라 장면이 만들게 했다.

말투를 가르는 것은 문체가 아니라 **그 사람이 지금 어떤 상태인가**다.

| 인물 | 상태 | 그래서 말이 |
|---|---|---|
| 아르카디 (60대) | 사흘째 혼자 문을 지켰다. 지쳤고 화가 쌓였다 | 툭툭 끊어지고 말끝을 흐린다. 반말 |
| 세린 (30대) | 며칠 못 잤다. 추궁당하면 먼저 방어한다 | 빠르고 자주 끊긴다. 궁지에 몰리면 더 짧아진다 |
| 미나 (40대) | 조용하고 다정하고 몹시 피곤하다 | 혼잣말이 섞인다. 화내는 대신 조용해진다 |
| 유나 (20대) | 무서워서 말이 많아지는 쪽 | 빠르고 횡설수설하고, 말하다 스스로 끊는다 |
| 델 박사 (60대) | 미안함을 잘 못 감춘다 | 하게체로 정중하지만 말끝이 흐려진다 |
| UNIT-7 | 기계 | **여기만 기계적이다.** 짧고 사무적. 단 한 번, 목록을 보고 처음으로 되묻는다 |

마지막 줄이 핵심이다. 사람이 전부 기계처럼 말하면 로봇이 주인공인 의미가 없다.
UNIT-7 이 딱 한 번 "…질의. 이 목록에 사람이 없는 이유." 라고 되묻는 장면이 서려면
그 전까지 **사람들은 사람처럼 말하고 있어야 한다**
(`AI_Robot_Base_Narrative_Design_Notes` §4 "명령 해석").

## 6. 인물과 인과관계

| id | 인물 | 있는 곳 | 콘셉트 |
|---|---|---|---|
| `caretaker` | 에어록 관리인 · 아르카디 | 에어록 | `airlock_caretaker_concept_v5.png` |
| `controller` | 방어망 관제원 · 세린 | 짧은 연결 통로 | `security_controller_concept_v5.png` |
| `keeper` | 수경재배사 · 미나 | 재배실 전실 | `hydroponics_keeper_concept_v5.png` |
| `junior` | 연구원 · 유나 | 침실 A | `researcher_junior_concept_v2.png` |
| `senior` | 선임 연구원 · 델 박사 | 육묘실 | `researcher_senior_concept_v2.png` |

```
관리인 ──lockdown──▶ 관제원을 추궁할 수 있다
관제원 ──power_cut──▶ 수경재배사에게 전할 수 있다   (+ promised: 함구 약속)
수경재배사 ──told_keeper──▶ keeper_bitter ──▶ 관제원의 인사가 바뀐다
                         (promised 해 놓고 전했으면 broke_promise ──▶ 더 차갑다)
수경재배사 ──junior_secret──▶ 젊은 연구원을 추궁할 수 있다  (+ kept_secret: 함구 약속)
젊은 연구원 ──▶ 선임에게 보고할 수 있다
선임 ──told_senior──▶ 젊은 연구원의 인사가 바뀐다
                    (kept_secret 해 놓고 보고했으면 broke_junior ──▶ 더 차갑다)
선임 ──priority_list──▶ 관리인 · 수경재배사 · 관제원 **모두**의 대사가 바뀐다
```

다섯 인물이 각자 **무언가를 만들고 무언가를 받는다**. 고립된 인물이 없다.
어느 쪽을 골라도 무언가를 잃는다 — 착한 선택 / 나쁜 선택이 아니라
**무엇을 포기하는가** 의 문제다 (설계 원칙: 내러티브 노트 §6).

## 7. 자산

콘셉트 PNG(1254×1254) → Native4 스프라이트는 `Tools/build_npc_sprites.py` 가 굽는다.

```
python Tools/build_npc_sprites.py            # → Assets/GameReady/Native4/character/npc/<id>/idle_01.png (80×80 아트 px)
python Tools/upscale_native4.py              # → GodotPrototype/assets/character/npc/… (×4 Nearest, 320×320)
python Tools/build_normal_maps.py character/npc
```

걷기 프레임은 없다. 살아 있는 느낌은 전부 절차적이다 — 숨쉬기(발 고정 세로 스케일),
플레이어 쪽으로 돌아보기(뒤집기 + 0.12초 스쿼시), 줄마다 한 번 끄덕이기.
플레이어가 idle 1프레임 + 절차적 반동으로 움직이는 것과 같은 방식이다.

## 8. 조작

| 키 | 하는 일 |
|---|---|
| W / ↑ | 말 걸기 (센트리건 다음, 단말기보다 먼저) |
| Space · E · Enter · 좌클릭 | 넘기기 (찍히는 중이면 한꺼번에 앉히기) / 선택 확정 |
| ↑ / ↓ (W / S) | 선택지 이동 |
| 숫자 1~9 | 그 번호의 선택지를 바로 고른다 — **번호가 화면에 보이는 방식에서만** 산다. 안 보이는 방식에서까지 먹으면 1~5 를 쓰는 대화 UI 랩의 방식 전환과 말없이 충돌한다 |
| F7 | 표시 방식 순환 (비교용) |

말을 **거는** 키(W/↑)는 넘기기에 넣지 않았다 — 한 번 누른 키가 말을 걸면서
첫 줄까지 넘겨 버리지 않게.

### 대화 중에는 마우스가 아무것도 못 한다

대화가 시작되면 `Main._lock_mouse(true)` 가 세 가지를 동시에 막는다.

1. **포인터를 잡는다** (`MOUSE_MODE_CAPTURED`) — 창 안에 갇히고 절대 좌표가 움직이지 않는다.
   대화 직전 좌표를 기억해 두었다가 끝날 때 그 자리로 되돌려 주므로 **조준점이 튀지 않는다.**
2. **카메라 리드를 끈다** (`GameCamera.lead_enabled`) — 이걸 안 끄면 대화 중에도 카메라가
   포인터 쪽으로 계속 흘러 화면이 가만히 있지 않는다. 끄면 `_lead` 가 0 까지 부드럽게 빠진다.
3. **조준·반동 계산 자체를 건너뛴다** — `Main._process` 의 대화 분기를 반동·조준보다 **앞**에 두었다.

## 9. 확인

```
godot --path GodotPrototype --headless --script res://tools/validate_map.gd
```
배치(벽 여유 · 천장 높이 · 중복 id · 몬스터 방 경고)와 **대사 나무 자체**를 검사한다 —
없는 노드를 가리키는 `next`/`to`, `FLAGS` 에 없는 플래그, 어디서도 닿지 않는 노드, 멈추는 노드.

```
godot --path GodotPrototype --script res://tools/npc_dialogue_shot.gd            # 말걸기 → 타자 → 선택지 → 화자 전환
godot --path GodotPrototype --script res://tools/npc_dialogue_shot.gd -- cast    # 다섯 인물 방마다 한 장
godot --path GodotPrototype --script res://tools/npc_dialogue_shot.gd -- chain   # 대사 나무를 끝까지 걸어 본다 (화면 없이)
godot --path GodotPrototype --script res://tools/npc_dialogue_shot.gd -- revisit # 실제 플레이로 인과관계 확인 (관리인 → 관제원)
```

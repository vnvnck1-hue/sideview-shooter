# 픽셀 애니메이션 프레임·타이밍 가이드

> 2026-09-21. 메탈슬러그 계열의 정통 사이드뷰 픽셀 아트 감각을 목표로 하는 제작 기준과 현재 Godot 프로토타입의 구현 상태를 함께 기록한다.
>
> 이 문서는 애니메이션의 **프레임 수·표시 속도·동작 커버리지**를 책임진다. 캐릭터 비율과 픽셀 규격은 [`CHARACTER_ART_GUIDE.md`](CHARACTER_ART_GUIDE.md), 공통 아트 규격은 [`ART_GUIDE.md`](ART_GUIDE.md)를 따른다.

## 1. 핵심 원칙

- 게임 로직과 화면 갱신은 60fps여도 픽셀 스프라이트는 보통 **8~12fps로 보이게** 재생한다.
- 프레임 수와 재생 fps는 다른 값이다. 예를 들어 8프레임 걷기를 8fps로 재생하면 한 사이클은 1초다.
- 모든 프레임을 같은 시간 동안 보여 주기보다 준비·접촉·회수 포즈는 길게, 총구 화염·충격 포즈는 짧게 유지한다.
- 프레임을 늘리는 것 자체보다 접지, 실루엣, 준비-타격-회수의 포즈 차이가 먼저다.
- 빠른 반응이 필요한 사격은 절차적 반동을 함께 써도 되지만, 절차적 이동만으로 주요 포즈의 부재를 전부 대신하지 않는다.

## 2. 동작별 권장 범위

| 동작 | 권장 프레임 수 | 권장 표시 속도 | 제작 메모 |
|---|---:|---:|---|
| 대기·호흡 | 4~8 | 3~8fps | 발을 고정하고 가슴·후드·장비만 작게 움직인다. |
| 걷기 | 6~10 | 8~12fps | 접지와 통과 포즈를 분명히 하고 이동 속도와 발걸음을 맞춘다. |
| 달리기 | 6~10 | 10~14fps | 걷기보다 보폭·전경·후경 팔 다이내믹을 크게 만든다. |
| 점프 | 5~8 | 상태 기반 | 도약·상승·정점·하강·착지를 속도나 상태에 맞춰 선택한다. |
| 총 발사 | 3~6 | 10~18fps 또는 짧은 홀드 | 준비·반동·회수가 읽혀야 하며 총구 섬광은 1프레임 수준도 가능하다. |
| 재장전·무기 교체 | 6~12 | 6~12fps | 탄창 분리·삽입·복귀의 핵심 포즈를 확보한다. |
| 피격 | 2~4 | 10~16fps | 즉각적인 충격 포즈 뒤 짧게 회복한다. |
| 사망 | 8~16 이상 | 8~12fps | 실루엣이 크게 변하는 주요 연출이므로 프레임 예산을 우선 배정한다. |
| 폭발·연기 | 6~12 | 10~18fps | 팽창은 빠르게, 소멸은 상대적으로 느리게 한다. |
| 보스·대형 기계 | 12~24 이상 | 8~12fps | 무게를 위해 준비·정지 포즈를 길게 홀드한다. |

### 프로젝트 기본 출발점

- 화면 갱신: 60fps
- 일반 스프라이트 샘플링: 10~12fps
- 플레이어: 대기 6, 걷기 8, 달리기 8, 발사 4, 점프 6, 피격 3, 사망 10~12프레임
- 중요한 원칙: **기본 동작은 4~8프레임, 눈에 띄는 연출은 8~16프레임**에서 시작한다.

이 수치는 모든 자산을 억지로 같은 길이로 만드는 규칙이 아니라, 프로토타입을 평가하고 프레임 예산을 배분하기 위한 기준선이다.

## 3. 현재 게임 구현 감사

판정 기준은 다음과 같다.

- **일치**: 권장 범위 안이거나, 절차적 보완까지 포함해 같은 목적을 충분히 달성한다.
- **부분 일치**: 동작은 읽히지만 프레임 수·속도·핵심 포즈 가운데 하나가 부족하다.
- **미달/미구현**: 정통 프레임 애니메이션 기준으로 필요한 동작이 없거나 대체 표현만 존재한다.

### 플레이어 — 부분 일치, 우선 보강 대상

런타임 단일 출처는 `GodotPrototype/scripts/player.gd`의 `CLIPS`, `ACTION_FRAME_COUNT`, 액션 지속시간이다.

| 동작 | 현재 구현 | 권장 기준 | 판정 |
|---|---|---|---|
| 대기 | 1프레임 + 2.6초 절차적 호흡 | 4~8프레임 | 부분 일치. 생동감은 있으나 옷자락·장비·실루엣 변화가 없다. |
| 걷기 | 4프레임, 최대 16fps | 6~10프레임, 8~12fps | 부분 일치. 프레임이 적고 최대 속도가 빠르다. |
| 달리기 | 4프레임, 최대 18fps | 6~10프레임, 10~14fps | 부분 일치. 속도감은 강하지만 정통 픽셀 포즈의 밀도는 낮다. |
| 앉기 | 4프레임, 12fps | 전환 3~6프레임 | 일치. |
| 발사 | 팔·머리·몸통의 절차적 반동, 섬광 0.03초 | 3~6프레임 또는 절차적 혼합 | 부분 일치. 반응성과 타격감은 좋지만 전용 키포즈가 없다. |
| 재장전 | 6프레임 / 1.15초, 약 5.2fps | 6~12프레임, 6~12fps | 프레임 수는 일치, 재생은 약간 느리다. 주요 포즈 홀드가 의도라면 허용 가능하다. |
| 구르기 | 6프레임 / 0.30초, 20fps | 6~10프레임, 약 10~16fps | 프레임 수는 적절하나 매우 빠르다. 잔상보다 포즈를 읽히게 할지 검토가 필요하다. |
| 점프 | 없음 | 5~8프레임 | 미구현. |
| 피격 | 없음 | 2~4프레임 | 미구현. |
| 사망 | 없음 | 8~16프레임 이상 | 미구현. |

참고로 `Frames/idle`과 `Frames/shoot` 폴더에는 각각 4장의 이미지가 있지만, 현재 런타임 플레이어는 분리형 `Split` 자산을 사용하며 대기는 1장, 사격은 절차적 반동으로 처리한다. 파일이 존재한다는 이유만으로 구현 완료로 계산하지 않는다.

### 연구원 NPC — 일치

`GodotPrototype/scripts/npc.gd` 기준으로 연구원 두 명은 다음 클립을 실제 재생한다.

- `idle_breathe`, `idle_notes`, `idle_listen`: 각 4프레임 / 3fps
- `walk`: 8프레임 / 8fps

대기는 권장 범위의 최소치이지만 느린 호흡에 적합하고, 걷기는 권장 프레임 수와 속도에 모두 들어온다. 현재 자산 중 정통 픽셀 애니메이션 기준과 가장 잘 맞는 사례다. 나머지 NPC는 1프레임과 절차적 호흡만 사용하므로 플레이어 대기와 같은 의미에서 부분 일치다.

### Toxic Tumor Crawler — 부분 일치

`GodotPrototype/scripts/crawler.gd`와 `crawler_meta.json` 기준:

| 동작 | 현재 구현 | 판정 |
|---|---|---|
| 걷기 | 4프레임 / 8fps | 속도는 일치, 프레임 수는 부족하다. |
| 점프 | 4프레임 / 8fps | 최소 권장치보다 1프레임 적지만 동작 상태와 위치 보간이 보완한다. |
| 공격 | 4프레임 / 10fps | 권장 범위의 하단으로 사용 가능하다. |
| 포효 | 4프레임 / 8fps | 읽히지만 강조 동작치고는 짧다. |
| 사망 | 4프레임 / 10fps | 권장 8~16프레임에 크게 못 미친다. 우선 보강 대상이다. |
| 벽 점프·코너 전환 자산 | 각 5프레임 / 10fps | 자산 규격은 적합하지만 현재 런타임에는 연결되지 않는다. 실제 벽 이동은 기본 클립과 절차적 회전·보간을 사용한다. |

크롤러는 이동 방식과 표면 전환이 다양해 포즈 설계는 풍부하지만, 핵심 클립 대부분이 4프레임으로 통일되어 있다. 특히 사망과 포효에 더 많은 프레임을 배정하면 존재감이 크게 좋아진다.

### 센트리와 효과 — 대체로 일치

- 센트리 전개: 8프레임 / 10fps. 기계 전개 동작으로 적절하며 현재 기준에 일치한다.
- 플레이어 총구 섬광: 0.03초. 60fps 기준 약 2화면 프레임이며 짧은 충격 섬광으로 적절하다.
- 중화기 총구 화염: 본체 0.075초, 십자 섬광 0.045초. 고정 프레임 애니메이션은 아니지만 팽창·감쇠와 연기·불꽃이 분리되어 타격감 목적을 충족한다.
- 불꽃·탄피·연기: 시간 기반 절차 애니메이션이다. 정통 스프라이트 프레임 수로 평가하지 않고, 픽셀 격자와 이동 궤적이 화면에서 지나치게 매끈해 보이지 않는지를 런타임에서 검수한다.

## 4. 종합 판정

현재 게임은 **전체적으로 B- 수준의 부분 일치**다.

- 잘 맞는 부분: 연구원 걷기, 센트리 전개, 크롤러·NPC의 8~10fps 타이밍, 짧은 총구 섬광, 큰 동작과 미세 반동의 분리.
- 덜 맞는 부분: 플레이어 걷기·달리기가 4프레임과 16~18fps에 집중되어 포즈보다 빠른 순환으로 속도감을 만든다.
- 가장 큰 공백: 플레이어 점프·피격·사망, 크롤러의 긴 사망 연출이 없다.
- 스타일상의 차이: 프로젝트는 전통적인 프레임 애니메이션만 쓰지 않고 스프링 반동, 스케일 호흡, 파티클, 절차적 보행을 적극 혼합한다. 반응성에는 유리하지만, 그대로 두면 메탈슬러그식 손그림 포즈 밀도보다는 현대적인 하이브리드 픽셀 게임에 가까워진다.

즉 **재생 타이밍은 상당 부분 맞고, 프레임 밀도와 동작 커버리지는 아직 부족하다.** 모든 효과를 프레임 애니메이션으로 바꿀 필요는 없으며, 플레이어와 주요 적의 실루엣이 크게 변하는 동작부터 프레임 예산을 늘리는 편이 효율적이다.

## 5. 권장 보강 순서

1. 플레이어 피격 3프레임을 추가한다. 짧고 반복해서 보게 되는 동작이라 적은 비용으로 체감이 크다.
2. 플레이어 걷기·달리기를 각각 6~8프레임으로 늘리고 10~14fps 범위에서 접지를 다시 맞춘다.
3. 플레이어 대기를 4프레임으로 만들고 현재 절차적 호흡은 축소하거나 제거해 중복 변형을 막는다.
4. 크롤러 사망을 8~12프레임으로 확장하고 마지막 포즈를 홀드한다.
5. 플레이어 사망 10~12프레임을 제작한다.
6. 실제 게임에 점프가 들어갈 때 속도 기반 5~6포즈를 추가한다.
7. 발사는 현재 절차적 반동을 유지하되, 필요하면 2~4장의 몸통·후드 반동 키포즈를 얹는다.

## 6. 신규 애니메이션 검수 체크리스트

- [ ] 프레임 수와 재생 fps를 별도로 기록했다.
- [ ] 접지 프레임에서 발바닥과 월드 이동 속도가 맞는다.
- [ ] 모든 프레임을 같은 간격으로 두지 않고 핵심 포즈 홀드를 검토했다.
- [ ] 정지 화면에서도 준비·타격·회수 포즈의 실루엣이 구분된다.
- [ ] 좌우 반전 시 무기·손·장비가 잘못 뒤집히지 않는다.
- [ ] 절차적 호흡·반동·트윈과 프레임 애니메이션이 중복되지 않는다.
- [ ] Nearest 필터와 정수 배율에서 픽셀 떨림이 없다.
- [ ] 실제 플레이 속도와 가장 축소된 카메라 배율에서 검수했다.

# 구역 지도 (Station Map)

*작성 2026-09-19 · 대상 `GodotPrototype/`*

플레이어가 보는 지도. **상시 HUD 미니맵이 아니라 단말기 화면 안의 개략도**다.
`survey`(구역 현황) 단말기의 지도 모듈이자, `security`(보안 관제) 단말기의 방어 그리드 화면이다.

컨셉의 뿌리는 단말기 시스템과 같다 — *"플레이어의 몸은 여기 있고, 시선만 스테이션 저편으로 건너간다"*
(`Docs/TERMINAL_SYSTEM_CONCEPT.md`).

---

## 1. 왜 단말기 안인가

- **상시 미니맵은 이 게임의 긴장을 없앤다.** "지금 어디인지, 옆 방에 무엇이 있는지 모른다" 가 이 게임의
  기본 상태다. 화면 구석에 항상 떠 있는 지도는 그 상태를 통째로 해제한다.
- **메트로배니아식 자동 지도(방에 들어가면 칸이 채워짐)도 결이 다르다.** 이 게임은 탐색 보상형이 아니라
  **관제형**이다. 지도는 "모아서 완성하는 수집물" 이 아니라 "기계에 가서 읽는 판독 결과" 여야 한다.
- 단말기 앞에서는 플레이어가 움직이지 못한다. 그래서 **지도를 펴는 행위 자체가 비용**이 된다 —
  몬스터가 도는 방에서 지도를 여는 것은 도박이다. 이 비용이 지도에 무게를 준다.
- 실무적으로도 단말기 안이 싸다. 역할 색(녹색) · CRT 프리셋 · 부팅 연출 · 조작 규칙이 이미 서 있고,
  `survey` 역할의 메뉴에는 **"구역 지도 — 이 단말에는 지도 모듈이 없습니다"** 라는 잠긴 줄이
  처음부터 자리를 비워 두고 있었다. 그 자리를 채운 것이 이 문서다.

---

## 2. 무엇으로 그리나 — 맵 데이터가 곧 지도다

지도 레이아웃 파일은 **없다**. 좌표를 손으로 찍지 않는다.
`RoomData.ROOMS` 의 문 그래프를 그대로 읽어 매번 짠다.

| 맵 데이터 | 지도에서 |
|---|---|
| `zone` | 가로 한 줄 (정비 → 승무원 → 전력 → 수경재배, 위에서 아래로) |
| `left_door` / `right_door` | 그 줄 안의 **순서**와 방과 방을 잇는 가로 실선 |
| `front_doors` | 줄과 줄을 잇는 **세로 점선**. 같은 줄 안이면 줄 위로 넘어가는 호(지름길) |
| `shape` (열 프로필) | 방 칸의 **실루엣** — 대형 홀은 가운데가 솟고 복도는 납작하다 |
| `props` 의 sentry · terminal · npc | 방 안의 ▲ · ▫ · ● 표시 |
| `spawn.max` (= `RoomData.danger`) | 실시간 판독 방의 개체 밀도 막대 |

`room_data.gd` 머리말에 손으로 그려 둔 지도 그림이 사실상 이 파일의 출력이다.
그래서 **맵을 고치면 지도가 따라온다** — 단말기 배치에서 겪었던 "두 곳이 어긋나는" 문제를 애초에 만들지 않는다.

### 줄 세우기

1. 구역마다 `left_door` 가 닫힌(또는 구역 밖을 가리키는) 방을 머리로 잡고 `right_door` 를 따라 걷는다.
2. 각 방의 폭은 `shape` 의 총 셀 수를 **4~13 셀로 눌러** 쓴다. 실제 비율대로 두면 격납고(32셀)가
   에어록(7셀)을 짓눌러 아무것도 안 보인다. **인접 관계는 정확히, 절대 크기는 버린다.**
3. 줄을 놓은 뒤, 아래 줄 전체를 좌우로 밀어 **정면문으로 이어진 방이 세로로 가깝게** 오도록 맞춘다
   (후보 오프셋 중 링크 거리 합이 최소인 것). 머리말 그림의 `[작업실]` 아래에 `[숙소 복도]` 가 오는
   그 정렬이 자동으로 나온다.

### 배율

가로·세로 배율이 다르다(`uy ≤ ux`). 실제 셀은 정사각이지만 21개 방을 한 화면에 넣으면서 층 차이를
남기려면 가로를 더 눌러야 한다. **모양의 상대 비율만** 지키고 절대 크기는 포기한 결과다 —
지도가 "방 목록"이 아니라 스테이션 단면도로 읽히는 것이 목적이지, 축척이 목적이 아니다.

## 3. 판독 등급 — 안개는 권한이다

방문 여부만으로 가리지 않는다. **센서 권한**과 **직접 경험**을 나눠 둔다.

| 등급 | 조건 | 지도에서 |
|---|---|---|
| `LIVE` | 이 단말기의 **관할 구역**(`TerminalData` 의 `grid`) | 밝은 실루엣 + 채움. 개체 밀도까지 읽힌다 |
| `KNOWN` | 플레이어가 **다녀온 방**(`AppFlow.visited`) | 흐린 실루엣. 이름·구조는 알되 밀도는 "판독 불가" |
| `DARK` | 둘 다 아님 | 빈 윤곽선과 `· · ·`. 이름도 내용도 뜨지 않는다 |

- 미판독 방도 **윤곽은 보인다**. "저기에 방이 하나 더 있다" 까지는 개략도에 남는 편이 낫다 —
  완전히 지우면 지도가 스테이션이 아니라 조각난 목록이 된다.
- `AppFlow.visited` 에는 **원격 조종으로 월드가 교체된 방도 들어간다.** 화면 너머로 봤어도 본 것은 본 것이다.
- 관할은 `security` 와 같은 `grid` 필드를 쓴다. 지금 배치로 두 대가 네 구역을 나눠 덮는다.

| survey 단말기 | 있는 곳 | 실시간 판독 |
|---|---|---|
| `survey_storage` | 창고 | 정비 구역 · 수경재배 구역 (창고는 정면문으로 재배실 전실과 붙어 있다) |
| `survey_cable` | 케이블 덕트 | 전력 구역 · 승무원 구역 (전력 간선을 타고 읽는다) |

## 4. 방어 그리드 — 목록 대신 지도에서 포탑을 고른다

`security` 단말기의 포탑 선택은 **같은 지도 위**에서 한다. 목록이 아니라 지도인 이유:
포탑 선택의 근거는 이름이 아니라 **"어느 방의 포탑인가"** 이기 때문이다.
"지금 몰려오는 쪽 앞 복도의 포탑" 을 고르는 일은 목록에서는 할 수 없다.

- 커서는 **관할 포탑에만** 선다. 관할 밖 포탑은 어두운 ▲ 로 그려지되 잡히지 않는다.
- **방어 그리드는 센서 판독과 별개다.** 그리드에 등록된 포탑은 미판독 방에 있어도 ▲ 와 방 이름이 뜬다 —
  "저 방에 포탑이 있는데 여기선 못 잡는다" 가 다음 단말기를 찾게 만드는 동기다.
- `ENTER` 로 채널 연결 → 기존 원격 조종 흐름(글리치 → 월드 교체 → 포탑 인계)을 그대로 탄다.
- 링크를 끊고 돌아오면 커서는 **방금 잡고 있던 포탑 위**에 그대로 있다.

## 5. 조작

| 상황 | 키 |
|---|---|
| 구역 지도 열기 | survey 단말기 접속 → 루트 메뉴 첫 줄 |
| 방어 그리드 열기 | security 단말기 접속 → 루트 메뉴 첫 줄 |
| 커서 이동 | `↑` `↓` `←` `→` / `W` `A` `S` `D` — 좌우는 같은 줄, 상하는 가장 가까운 열의 다른 줄 |
| 포탑 접속 (그리드) | `ENTER` / `Space` |
| 뒤로 | `ESC` / `Q` |

## 6. 파일

| 파일 | 역할 |
|---|---|
| `scripts/station_map.gd` | 지도 전부 — 문 그래프에서 레이아웃 산출(정적·캐시) + 실루엣·연결선·커서·판독 정보 그리기 |
| `scripts/terminal_screen.gd` | `State.MAP`(survey) · `State.GRID`(security) 에서 지도를 띄우고 커서 입력을 넘긴다 |
| `scripts/terminal_data.gd` | `grid` 필드 — security 는 접속 권한, survey 는 실시간 판독 범위. `grid_of()` |
| `scripts/app_flow.gd` | `visited` — 다녀온 방 기록(static, 새 게임에서만 비운다). `visit()` |
| `scripts/main.gd` | 방을 조립할 때마다 `AppFlow.visit()` |
| `tools/map_shot.gd` | 지도 스크린샷 (`--script res://tools/map_shot.gd` → `user://shots/map_*.png`) |
| `tools/test_terminal_flow.gd` | 지도 골격 검사(방 누락·줄 안 겹침·정면문 양끝) + 그리드 지도에서 포탑 선택까지 |

## 7. 남은 것 / 확장 여지

- **판독 시각.** 지금 `KNOWN` 은 "과거 기록" 이라고만 쓴다. 실제로 언제 읽었는지를 방마다 남기면
  "3시간 전 판독" 같은 문구로 정보의 신선도를 드러낼 수 있다.
- **`rewire` 의 `cameras` 회로와 연동.** 감시 카메라 회로를 내리면 실시간 판독이 멈추게 —
  배전 결과가 월드에 반영되지 않는 것은 단말기 컨셉 문서 §7 에도 남아 있는 숙제다.
- **링크 품질.** 거리·전력에 따라 지도에 잡음이 끼게.
- 지도에서 **잠긴 정면문**을 구분해 표시하기 (지금은 열림/닫힘을 측벽문만 반영한다).
- 방 이름이 긴 경우 가로로 잘린다. 줄임표 또는 두 줄 배치 검토.

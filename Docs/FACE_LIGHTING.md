# 면 라이팅 — 프랍의 면을 손으로 나눠 방향별로 반응시키기

*2026-09-22 · 사물함·작업대·안락의자 3종 적용 완료. 나머지 프랍은 필요한 것부터 하나씩.*

## 무엇을

3면(또는 2면)이 보이는 상자꼴 프랍에 **면 경계를 직접 그어** 상판·측면·정면을 나눠 두면,
각 면이 그 방향에 있는 광원에만 반응한다. 광원이 왼쪽이면 좌측면만, 위면 상판만 켜진다.

구현은 **노멀맵**이다. 면마다 상수 노멀을 주는 것뿐이라 셰이더·런타임 코드는 건드릴 것이 없다 —
`prop_surface` / `lit_surface` 가 이미 `NORMAL` 을 `lit_light()` 에 넘기고 있어서, 노멀이 면별로 갈라지는
순간 `dot(N, L)` 이 매 프레임 광원 방향을 따라간다.

## 왜 지금은 안 되는가

`Tools/build_normal_maps.py` 는 노멀을 원화의 **밝기 + 실루엣 베벨**에서 Sobel 로 추론한다. 그래서

- 평평하게 칠한 상판·측면은 밝기 변화가 없으니 전부 `(0,0,1)` — **정면을 보는 평면**으로 취급된다
- 면 경계는 밝기 *차이*가 있는 선이라 두 개의 평면이 아니라 **그 선 위의 얇은 융기**로 해석된다
- 결과적으로 모든 프랍이 조명 방향과 거의 무관하게 비슷하게 둥글둥글 반응한다

면 맵은 추론하지 않고 **면을 선언한다**. 그게 차이의 전부다.

## 왜 `light_mask` 로 하지 않는가

"면마다 스프라이트를 쪼개고 면별로 광원을 배정" 하는 방식은 이 프로젝트에서 특히 나쁘다.

1. `light_mask` 는 **정적 이진 배정**이다. 광원이 프랍 왼쪽에서 오른쪽으로 지나가면 왼쪽 면이 계속 밝다.
   총구 화염·탄착 라이트처럼 움직이는 광원이 주인 게임에서 치명적이다.
2. 45° 광원에 대한 **부분 반응이 없다.** 켜짐/꺼짐뿐이라 경계가 계단처럼 튄다.
3. 프랍 하나가 캔버스 아이템 3개가 된다 — `Lighting` 의 **아이템당 라이트 15개 한도**(`tools/light_budget.gd`)
   관리가 그만큼 어려워진다.

노멀맵은 셋 다 해당되지 않는다. 아이템 수도 그대로다.

## 파일 배치

```
GodotPrototype/assets/props/workshop_locker_game_scale.png          원화
GodotPrototype/assets/faces/props/workshop_locker_game_scale.png    면 맵 (내가 칠하는 것)
GodotPrototype/assets/normals/props/workshop_locker_game_scale.png  결과 (Lighting.textured 가 읽는 자리)
```

`assets/faces/` 아래는 `assets/` 아래와 **같은 상대경로**를 쓴다. 프랍뿐 아니라 문·타일·캐릭터도 같은 규약이다.

## 칠하는 색

면 맵은 원화와 **같은 크기**의 PNG 다. 순색이라 Aseprite 팔레트에 올려 두고 페인트통으로 부으면 된다.

| 색 | 면 | 향하는 방향 |
|---|---|---|
| 파랑 `#0000FF` | 정면 | 화면 쪽 (기울지 않음) |
| 빨강 `#FF0000` | 상판 | 위 |
| 초록 `#00FF00` | 좌측면 | 왼쪽 |
| 노랑 `#FFFF00` | 우측면 | 오른쪽 |
| 자홍 `#FF00FF` | 밑면 | 아래 (돌출부 아랫면) |
| 청록 `#00FFFF` | 좌상 경사 | 왼쪽 위 45° |
| 흰색 `#FFFFFF` | 우상 경사 | 오른쪽 위 45° |

- **비워 둔 곳(알파 0)은 기존 자동 노멀을 그대로 쓴다.** 큰 면 두세 개만 칠하고 나머지는 두어도 된다.
  (`soft` 가 0 보다 크면 비워 둔 곳은 가까운 면에서 번져 온 값으로 채워지고, 번짐 사거리 밖에서만 자동 노멀로 돌아간다)
- 순색에서 조금 어긋나도 가장 가까운 항목으로 붙잡힌다. 다만 **안티에일리어싱은 끄고 칠한다.**
- 면이 더 필요하면 `scripts/face_normal.gd` 의 `PALETTE` 에 줄을 추가하면 된다.

## 작업 순서

### 1. 랩에서 나누고 본다

로비 → **조명·면 랩** (`scenes/FaceLab.tscn`). `main.gd` 를 상속해 **실제 게임 그대로** 돌아간다 —
플레이어·총·몬스터·조명이 전부 본편과 같다. 조명 쪽은 `Docs/LIGHT_TUNING.md`.

| 키 | |
|---|---|
| `F5` | 편집 패널 접기/펴기 |
| **우클릭** | 화면에서 고르기 — 가까운 광원, 없으면 커서 아래 **프랍** |
| **`N`** | 면 노멀 ↔ 기존 자동 노멀 **A/B** |
| **`M`** | 면 맵 겹쳐 보기 — 내가 나눈 경계가 원화와 맞는지 |
| **`F12`** | 면 맵 다시 읽고 다시 굽기 — 그림 고치고 저장한 뒤 |
| **`P`** | 마우스 광원 켜기/끄기 — 포인터를 광원 삼아 면을 훑는다 (`Shift+P` 고정 · 휠 반경 · `Shift`+휠 세기 · `Ctrl`+휠 높이) |
| 패널 슬라이더 | **고른 프랍의** 기울기 `tilt` · 디테일 `detail` · 번짐 `soft` |
| 패널 버튼 | [면 수치 저장] → `faces/tuning.json` · [템플릿 만들기] (Shift 누른 채면 덮어씀) |
| 게임 조작 | `A`/`D` 이동 · 마우스 조준 · 좌클릭 사격 · `R` 재장전 · `F3` 줌 · `F1` 로비 — 본편과 동일 |

템플릿을 만들면 콘솔에 절대경로가 찍힌다. Aseprite 에서 **원화 위에 레이어로** 올려놓고,
면 경계를 긋고 각 면을 부은 뒤 면 맵 레이어만 저장한다. 랩으로 돌아와 `F12`.

임포트를 거치지 않고 원본 PNG 를 직접 읽으므로 **에디터 재임포트를 기다릴 필요가 없다.**

### 2. 확정되면 자산에 굽는다

```bash
godot --path GodotPrototype --headless --script res://tools/bake_face_normals.gd
```

`assets/faces/` 아래 면 맵을 전부 찾아 `assets/normals/<같은 상대경로>` 에 덮어쓴다.
굽고 나면 게임 코드는 건드릴 것 없이 그대로 적용된다. 일부만 구우려면 인자로 이름 조각을 준다:
`-- locker workbench`.

수치는 랩이 `Ctrl+S` 로 저장한 `faces/tuning.json` 을 **자산별로** 읽는다 (아래 "수치" 절).

`Tools/build_normal_maps.py` 는 **면 맵이 있는 파일을 건너뛴다.** 자동 베이커를 다시 돌려도
여기서 구운 것이 날아가지 않는다.

## 수치 — 자산마다 다르다

| | 기본 | |
|---|---|---|
| `tilt` | 45° | 면이 정면에서 기울어지는 각도. 올리면 면끼리 명암차가 커지지만(입체감↑) 면이 광원을 등지는 각도도 빨리 와서 더 자주 어두워진다 |
| `detail` | 0.35 | 기존 자동 노멀의 xy 를 섞는 비율. 0 이면 완전히 평평한 면, 0.3~0.4 면 면 방향은 유지한 채 리벳·홈 같은 표면 요철이 살아남는다 |
| `soft` | 0 px | 면과 면 사이 **번짐 폭**. 0 이면 칠한 대로 딱 갈라진다. 0 보다 크면 칠한 면이 코어가 되어 주변으로 번져 경계가 그라데이션이 된다 |

### 딱딱한 면 / 부드러운 면

**각진 것과 둥근 것은 같은 값을 쓰면 안 된다.** 사물함·작업대처럼 모서리가 뚜렷한 것은 면이 딱 갈라져야
형태가 사는데(`soft: 0`), 소파처럼 경계가 아예 없는 것에 같은 방식을 쓰면 **있지도 않은 모서리가 생겨**
어색해진다. 둥근 것은 반대로 간다:

> 각 면을 **최소한의 면적(코어)만** 찍고, `soft` 를 키워 그 사이를 번지게 한다.

동작은 노멀 필드의 **정규화 컨볼루션**이다 — 칠한 면의 노멀에 가중치 1 을 주고 가중치까지 같은 커널로
흐린 뒤 나눈다. 그래서 코어 사이는 두 방향이 자연스럽게 보간되고, 아무 코어도 가깝지 않은 곳은
가중치가 0 으로 떨어져 **기존 자동 노멀로 되돌아간다**. 안락의자는 실루엣의 33% 만 칠해져 있고
나머지는 전부 번짐이 만든 것이다.

### 자산별 덮어쓰기

수치는 자산별로 덮어쓸 수 있다 (`GodotPrototype/faces/tuning.json`):

```json
{
  "tilt": 45.0, "detail": 0.35, "soft": 0.0,
  "assets": {
    "props/workshop_armchair_game_scale.png": {"tilt": 34.0, "detail": 0.45, "soft": 22.0}
  }
}
```

랩의 슬라이더는 **고른 자산의** 값을 바꾸고, [면 수치 저장] 이 그 자산 항목으로 저장한다.
베이커가 같은 파일을 읽으므로 랩에서 맞춘 값이 그대로 구워진다.
`FACE_TILT=50 FACE_DETAIL=0.3` 환경변수를 주면 자산별 값을 무시하고 전부 그 값으로 굽는다 (한 번에 A/B 할 때).

**앰비언트가 면 대비를 먹는다.** `Lighting.AMBIENT` 는 지금 `(0.42, 0.43, 0.55)` 로 꽤 높다.
면을 나눴는데 기대보다 밋밋하면 `tilt` 보다 앰비언트를 먼저 의심한다 (랩 패널의 조명 → `ambient`).

## 알아 둘 것

- **림라이트도 `NORMAL` 을 쓴다** (`lit_common.gdshaderinc` 의 프레넬 항). 면 경계에서 림이 끊기는 게
  거슬리면 `rim_strength` 나 프레넬 계수를 조정하거나, 림에만 부드러운 실루엣 노멀을 따로 쓰는 것을 검토한다.
- 라이트의 `height` 가 0 이면 표면과 평행해 **노멀이 아예 반응하지 않는다.** 램프 140 · 총구·탄착 90
  (`Lighting.LAMP_HEIGHT`). 랩 패널의 조명 쪽에서 광원마다 확인·조절할 수 있다 (`Docs/LIGHT_TUNING.md`).
- 플랫 면 노멀은 타협이 아니라 **픽셀아트에 더 맞는 결과**다. 그라디언트 노멀은 명암이 부드럽게
  굴러가지만, 플랫 면은 경계에서 딱 끊겨서 하드에지 박스 프랍의 조형과 일치한다.

## 현재 상태 (2026-09-22)

세 프랍이 나뉘어 있고 **셋 다 실제 자산으로 구워져 인게임·테스트 씬·랩에 적용돼 있다.**

| 프랍 | 나눈 방식 | tilt / detail / soft |
|---|---|---|
| 사물함 `workshop_locker` | 면을 꽉 채워 3분할 — 좌측면 `x<99` · 상판 `y<58` · 정면 | 45° / 0.35 / **0** |
| 작업대 `workshop_workbench` | 면을 꽉 채움 — 상판 윗면·앞 마구리, 아래 선반 윗면·앞면. 다리·버팀대·바이스는 **비워 둠**(자동 노멀) | 45° / 0.35 / **0** |
| 안락의자 `workshop_armchair` | **코어 14개만** (등받이 크라운·좌우 어깨·좌우 날개 바깥·정면, 양 팔걸이 윗면·바깥 끝·안쪽, 방석 윗면, 앞치마). 실루엣의 33% 만 칠하고 나머지는 번짐이 채운다 | **34° / 0.45 / 22px** |

의자만 값이 다른 이유는 위 "딱딱한 면 / 부드러운 면" 참고. 각진 프랍처럼 면을 꽉 채우고 `soft: 0` 으로
구우면 팔걸이·등받이에 있지도 않은 모서리가 생겨 둥근 형태가 깨진다.

경계는 전부 **근사치**다 — 원화를 보고 좌표로 자르거나 실루엣에서 뽑은 것이라 손잡이·경첩·솔기 주변이
어긋나 있다. 랩에서 `M` 으로 겹쳐 보면 바로 보이고, 면 맵만 고쳐 저장한 뒤 `F12` → 베이커를 다시 돌리면 된다.

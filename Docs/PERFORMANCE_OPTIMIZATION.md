# 전투 성능 최적화 (2026-09-28)

버그봇 전투(F10)에서 몬스터·액션이 늘수록 렉이 걸리던 문제. **화면은 그대로 두고** 비용만 줄였다.

## 결과

격납고, F10 전투 최대 압박(버그봇 3 + 몬스터 14 상한 + 플레이어 초당 10발), 120초, 고정 델타:

| | 평균 | p95 | p99 |
|---|---|---|---|
| 이전 · 창 모드 | 32.2 ms | 60.9 ms | 77.4 ms |
| 이후 · 창 모드 | 14.7 ms | 19.1 ms | 20.2 ms |
| 이전 · 헤드리스(스크립트만) | 23.7 ms | 54.6 ms | 73.7 ms |
| 이후 · 헤드리스 | 8.9 ms | 13.3 ms | 16.8 ms |

5분 연속 전투에서 프레임 시간·노드 수·객체 수가 늘지 않는다(고아 노드 0).

## 원인과 조치

렉의 대부분은 GPU 가 아니라 **GDScript CPU** 였다(헤드리스와 창 모드 차이가 ~5ms 뿐).

1. **버그봇 보행 IK (프레임의 65%)** — `SpiderLegIK.margin()` 이 hip 후보마다 Dictionary 를 만들며 최대 28 피치 × 12 요를
   평가했고, 보행 판정이 서브스텝마다 수십 번 불렀다. 같은 식을 같은 순서로 계산하는 할당 없는 탐색 + 입력 메모 + 피치 하한 가지치기.
2. **기동·정지 중 20~34ms 스파이크** — 몸 높이가 매 서브스텝 바뀌어 보폭 측정(IK 72회)을 매번 다시 했다. 버그봇이 전투불능·수리될
   때마다 1~2초씩. 조건이 바뀐 순간의 입력을 적어 두고 실제로 필요할 때 그 입력으로 잰다(결과 동일).
3. **누수** — 원거리 회수·F10 종료로 사라진 크롤러의 체액 SparkBurst(+사망 라이트)가 방을 나갈 때까지 매 프레임 돌며 쌓였다.
4. **스폰 끊김** — 크롤러마다 메타 JSON 파싱 + SpriteFrames 조립 → 자산 폴더별 공유.
5. 알갱이 벽 판정 O(열 수) → O(1), 체액 자국·육편 머티리얼/텍스처 공유, 빈 SparkBurst·식은 탄흔의 매 프레임 작업 생략,
   셰이더(먼지·바닥 안개 조기 종료, 마스크 없는 재질의 마스크 읽기 생략).

## 검증 도구 (tools/)

- `perf_bugbot_stress.gd` — 위 표의 부하 측정. `-- [초] [간격]`. 창 모드는 수직 동기화를 끄고 잰다.
- `trace_determinism.gd` — 버그봇 몸통·발·관절, 몬스터 위치·체력을 프레임별로 기록. 전후 출력이 한 글자라도 다르면 결과가 바뀐 것.
  (소리 변주를 전용 난수로 옮겨 같은 시드면 전투가 매번 똑같이 흐른다.)
- `capture_frames.gd` — 같은 시나리오의 화면을 원시 RGB 로 저장. 이번 변경은 5개 프레임(3440×1440)이 기준점과 **픽셀 단위 동일**.
  카메라가 실제 마우스 커서를 따라가므로 캡처 중엔 마우스를 두지 말거나 `pin` 인자를 준다.

## 되돌린 것 (화면이 달라져서)

- 다 꺼진 탄착 라이트를 일찍 지우기 — 엔진 내부 라이트 순서가 바뀌어, 한 아이템에 라이트가 15개를 넘는 자리에서 빠지는 라이트가 달라졌다.
- 완전 투명 픽셀의 림 탐색 생략 — 라이트 패스가 알파 0 픽셀도 밝혀 보이게 만든다.

## 남은 것

- 수리된 버그봇이 처음 걸음을 뗄 때 보폭 측정 한 번(10~18ms, 버그봇당 복귀마다 1회).
- 에셋은 이미 무손실·밉맵 없음(도트 최근접 필터에 맞음). 거대종 프레임(1086×1512)의 넓은 투명 여백은 GPU 채움 비용이지만,
  잘라내려면 프레임 오프셋·림 샘플링을 함께 맞춰야 해 이번엔 손대지 않았다.

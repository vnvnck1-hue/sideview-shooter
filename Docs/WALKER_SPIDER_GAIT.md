# 거미형 4족 보행

이 기체의 네 다리는 공간에서 옆으로 벌어진 거미형 관절이다. 원화의 사선 구도는 그 구조를 화면에 보여 주는 시점이다. 화면에 보이는 선의 길이를 실제 뼈 길이로 고정하면, 카메라 쪽을 향해 짧게 보이는 다리는 걷는 데 필요한 가동 범위를 잃는다.

## 계산 방식

- 원화 위에서 정한 26개 피벗은 편집 기준으로 그대로 보관한다. 저장 파일을 자동으로 교정하거나 덮어쓰지 않는다.
- `SpiderLegIK`가 각 다리에 깊이를 부여한다. 몸체 연결 → 고관절 → 무릎 → 발목 → 발끝의 네 마디를 실제 공간의 고정 길이로 계산한다.
- 몸체에 붙은 첫 관절은 다리를 앞뒤로 회전시킨다. 나머지 관절은 발의 접지 목표에 맞춰 접힌다. 최종 관절을 사선 화면에 투영한다.
- 화면의 `Bone2D` 길이는 투영에 따라 달라진다. 이것은 물리적인 뼈가 늘어나는 것과 다르다. 검증은 3D 뼈 길이와 화면 본의 끝점 일치를 각각 검사한다.
- 두 대각 쌍이 교대한다. 지지 중인 발은 월드 접점을 유지하고, 이동하는 발만 들어서 다음 접점으로 옮긴다. 달리다가 도달 한계에 걸려 속도가 줄어도 이동 입력을 기준으로 다음 걸음을 준비한다.
- 사용자가 FR 발끝을 옮기면 예전의 가려진 발 추정 오프셋을 더하지 않는다.

## 확인

로비 → **사족보행 랩**은 이제 실제 인게임 아트와 보행 수치를 함께 조정하는 [보행 튜닝 화면](WALKER_TUNING.md)이다. A/D 이동, Shift 달리기, Space 점프이며 조준은 이동 방향과 독립적이다. 상단 **피벗 · 키프레임**으로 원화 편집기를 열 수 있다. 그 편집기의 **보행 확인**은 원화 뼈대로 공간 관절을 확인하는 화면이다.

인게임 `WalkerUnit`도 `WalkerSpiderAdapter`를 통해 같은 `SpiderLegIK`를 사용한다. 기체가 생성될 때 저장 문서의 **다리 피벗**을 읽고 게임의 배율·원점·좌우 방향으로 변환한다. 랩에서 Ctrl+S로 저장한 뒤 게임에 다시 진입하면 적용된다. 몸통/포신은 기존 인게임 아트와 독립 조준 경로를 유지하며, 키프레임 클립을 인게임에 자동 재생하는 기능은 별개다.

원화 한 장에서 깊이와 관절축을 완전히 복원할 수는 없다. 현재 깊이는 네 다리가 옆으로 벌어진다는 구조에 따라 정한 초기값이며, yaw·pitch 기준과 허용 범위, 무릎 벌림은 보행 튜닝 화면에서 조절한다. 원화/키프레임 탭은 기존의 2D 자세 지시 방식이다. 보행 자세의 **캡처**는 투영된 관절 방향을 2D 키로 가져오며, 공간 보행을 그대로 굽는 기능은 아니다.

```text
godot --headless --path GodotPrototype --script res://tools/validate_spider_gait.gd
godot --headless --path GodotPrototype --script res://tools/validate_spider_runtime.gd
godot --path GodotPrototype --rendering-method gl_compatibility --audio-driver Dummy --fixed-fps 60 --script res://tools/capture_spider_gait.gd -- current
```

검증은 기본 피벗과 저장 피벗을 모두 사용하며 원화와 저장 문서의 해시가 변하지 않았는지 확인한다. 렌더 캡처는 실제 랩 UI와 저장 문서를 사용한다.

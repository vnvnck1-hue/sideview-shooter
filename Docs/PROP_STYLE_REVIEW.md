# 프랍 스타일·밀도 검수와 연구시설 시험 기록

> **v1.11 이후의 위치: 과거 실패·분석 기록.** 아래 r1–r3 및 batch2 r4는 승인 원화의 보존형 변환 성공 사례가 아니다. batch2 r4도 사용자의 톤 불일치 피드백으로 채택되지 않았다. 당시의 8~16색 예산, 작은 고정 캔버스, 구조 재설계 체크리스트는 현재 제작 지침으로 재사용하지 않는다. 현재 원칙은 [ART_GUIDE §0](ART_GUIDE.md), 실행 절차는 [ASEPRITE_PIPELINE](ASEPRITE_PIPELINE.md)을 따른다. 기존 리소스 분석은 원화 생성의 그림체 근거이며, 승인 후 변환의 직접 기준은 승인 원화다.

2026-09-20. 상위 규격: [ART_GUIDE §10–11](ART_GUIDE.md). 실행: [ASEPRITE_PIPELINE](ASEPRITE_PIPELINE.md).
최신 v1.8의 **1 art px = 4 world px, 화면 ×2~×6(기본 ×3)**와 런타임 변형 제한을 읽고 반영했다. 이후 v1.9는 규격을 바꾼 것이 아니라 승인 절차를 보강한 것이다.

이 문서는 프랍 제작자가 실패 원인을 확인하기 위한 분석·반례·당시 체크리스트다. 과거 시각 판단과 검사 기록은 보존하되 현재 승인이나 현재 정책으로 해석하지 않는다.

## 1. 실패를 어떻게 정의하는가

연구시설 15종의 이전 Lua 제작은 크기·이진 알파·색 수는 맞았지만, 큰 사각형과 테두리 위주였다. 상판 두께, 받침 구조, 문 패킹, 유리 내부의 깊이 등 **중간 규모 정보**가 빠졌다. 따라서 규격 통과가 가능한 블록아웃이었지 완성 아트가 아니었다.

원인과 재발 방지:

| 원인 | 금지할 판단 | 바뀐 작업 방식 |
|---|---|---|
| 실제 사용 중인 자산과 충분히 비교하지 않음 | 참고 그림을 봤다는 이유로 스타일 일치 주장 | 런타임 경로·해시를 고정하고 기존/이전/후보 비교판 저장 |
| 깨끗한 시설을 단순한 면으로 해석 | 녹이 없으므로 구조·재질도 생략 | 패널 단차·실·힌지·유리 두께·결합부로 밀도 구성 |
| 7~9색과 단순 도형을 효율로 취급 | 색 수가 적고 격자가 맞으면 고품질 | 8~16색은 상한/예산. 큰 형태·구조·기능과 재질 역할이 먼저 |
| 규격 검사 직후 15종과 타일을 자동 배포 | 자동 검사 성공 = 검수 완료 | staging → 시각 중단 게이트 → 선택 파일 반입 |
| 생성한 프리뷰를 승인 증거로 간주 | 파일 생성 = 눈으로 확인 | 실제 본 배율·관찰·수정·미검증 항목을 기록 |

**기존 RGB 수천 색, 새 그림 8색** 같은 수치만으로 품질을 설명하지 않는다. 이전에 언급된 약 15% 대 52% 변화율은 프리베이크/네이티브 혼용, 격자 위상, 투명 영역 처리 조건이 달랐으므로 비교 근거에서 제외한다.

## 2. 기준은 실제 런타임 프랍

`RoomData.PROP_DIR`와 `Room._prop_path()`는 `GodotPrototype/assets/props/`를 사용한다. `Assets/GameReady/Props/`의 프리베이크본이나 과거 HEAD 파일을 이번 수정 직전 아트로 오인하지 않는다.

다음은 실제 PNG를 열어 본 관찰이다. 색·모양을 복사하기보다 **정보가 조직되는 방식**을 가져온다.

| 기준 파일 (`GodotPrototype/assets/props/`) | 큰 형태·약한 원근 | 중간 구조·재질 | 작은 기능 정보·휴지 면적 | 연구시설에 옮길 원리 |
|---|---|---|---|---|

공통 스타일: 어두운 자주/회색 계열의 결합 암부, 절제된 따뜻한 본체, 국소적인 밝은 면, 약한 깊이, 비어 있는 면과 기능부의 밀도 차이. 기존 자산에도 미세 색 흔들림이 많으므로 ×6의 모든 점을 복제하지 않는다. 동일한 노이즈가 아니라 동일한 **구조적 설득력**이 목표다.

### 비교 격자와 재현성

`prepare_prop_style_review.ps1`은 16개 위상 `(x,y)=0..3`을 검사한다. 각 4×4 셀의 유효 픽셀이 동일한 RGBA인지 비교하고, 투명 픽셀의 숨은 RGB는 무시한다. 불일치가 1개라도 있으면 손실 없는 추출을 거부한다. 검증된 셀당 한 색을 보존하고 부분 경계 셀은 포함한다. 결과를 다시 4배 확대해 원래 위상으로 자르면 원본과 동일해야 한다.

| 프랍 | 월드 파일 크기 | 격자 위상 x,y | 비교용 art 셀 | 비고 |
|---|---:|---:|---:|---|
| 작업대 | 443×235 | 2,2 | 112×60 | 가장자리 부분 셀 포함 |
| 캐비닛 | 370×315 | 0,1 | 93×80 | 신규 제작 표의 92×80으로 강제 변형하지 않음 |
| 소파 | 286×240 | 0,3 | 72×61 | 1px 경계 패딩 때문에 새 규격 72×60과 다름 |
| 수경 제어기 | 168×180 | 2,3 | 43×46 | 소형 장비 기준 |
| 수경 탱크 | 171×380 | 2,1 | 44×96 | 세로 유리 장비 기준 |
| 수경 싱크 | 190×185 | 3,1 | 48×47 | 작업 높이/볼 깊이 기준 |

모두 셀 내 불일치 0. 원본 경로·SHA256·추출 로그는 `Assets/Generated/PropStyleLab/references/provenance.json`에 있다. 플레이어도 런타임 `character/Frames/idle/idle_01.png`에서 같은 방식으로 추출했다(80×81 비교 셀). 이 파생 이미지는 리뷰 전용이며 신규 제작 규격이나 교체 원본이 아니다.

### 조립에서 발견한 별도 문제

`review-r3/assembly-*-x2.png`와 ×3·×6은 실제 배경 텍스처, 기존 작업대, 후보 3종, 런타임 플레이어를 동일 배율로 놓은 **오프라인 접지 검토용 부분 장면**이다. 바닥 띠는 비교용이다. 실제 방 프레임·광원·노멀맵·가림·충돌은 검증하지 않았으며 엔진 스크린샷으로 부르지 않는다.

- 작업실 어두운 배경에서는 플레이어의 붉은 실루엣과 후보 프랍의 낮은 채도가 분리된다.
- 현재 연구시설 배경은 밝은 청회색이다. 후보의 중간 회색 금속 면과 대비가 약해진다. 이는 프랍을 더 밝게 칠할 문제가 아니며 **환경 세트 런타임 승인은 보류**한다. 이 시험에서 배경/타일을 임의 수정하지 않았다.
- 작업실 런타임 배경 시트는 4×4 동일색 검사에 실패했다(최선 위상에서도 82,171 픽셀 불일치). 프랍 추출처럼 조용히 축소하지 않고, 원래 월드 해상도 사본을 보존해 화면 배율 `scale/4`의 Nearest로만 표시했다. 이 별도 배경 문제를 프랍 규격 결함이나 새 네이티브 기준으로 혼동하지 않는다.
- 실제 `RoomData.FLOOR_Y`는 486이다. 가이드의 신규 타일 목표 488로 이번 프랍 시험이 몰래 바꾸지 않는다. 비교 시트의 접지선은 로컬 기준이며 엔진 좌표 검증이 아니다.

## 5. 수치는 원인 찾기에만 쓴다

전체 불투명 픽셀의 오른쪽/아래 **둘 다 불투명인 인접 쌍**만 분모로 삼는다. RGB 채널 차이 중 최댓값이 24 이상인 쌍의 비율을 계산한다. 투명 배경과 실루엣 경계는 제외한다. 24는 작은 RGB 흔들림을 일부 배제하는 고정 진단 조건이지 합격선이 아니다. 색상별 면적·큰 구조·재질 의미·인접 쌍 분포를 해석하지 못하는 지표다.

| 비교 쌍 | 실제 기존 프랍 | 이전 블록아웃 | r1 | r2 | r3 |
|---|---:|---:|---:|---:|---:|
| 작업대 | 33.10% | 21.38% | 30.51% | 34.20% | 36.39% |
| 보관장 | 30.82% | 20.48% | 28.97% | 32.31% | 34.35% |
| 배양통 | 45.48% | 19.38% | 25.08% | 29.62% | 32.01% |

작업대 r2가 기준보다 높아도 평면/경계 문제가 남았고 r3 마감이 필요했다. 배양통은 기준보다 낮지만 내부 대상이 식물과 검체로 다르다. **기준 수치를 넘기기 위해 점·줄을 추가하는 것을 금지한다.** 수경 탱크의 높은 값에는 잎·줄기·기존 베이크 잡티가 함께 들어 있다.

r3 규격: 작업대 96×53/15색, 보관장 56×75/14색, 배양통 52×84/16색. 셋 모두 부분 알파 0, 불투명 경계 0, 편집 레이어 5, 프레임 1. `.aseprite` 재출력과 PNG의 모든 픽셀 일치를 검사했다. 원본 해시와 검사 범위는 `review-r3/verification.json`에 있다. 이는 **규격 검증 결과**다.

## 6. 당시 체크리스트 — 현행 실행 절차로 사용하지 않음

1. 최신 가이드와 코드의 화면 배율을 대조한다. 충돌이 있으면 기록하고 기존 값을 몰래 변경하지 않는다.
2. 실제 사용하는 기준 2~3개를 고른다. 경로·해시·격자를 고정하고 같은 역할의 큰/중간/작은 정보를 표로 적는다.
3. 캔버스·실루엣 목표·접지·팔레트 역할을 잠근다. 중요한 정보는 2×2 이상, 1px 디테일은 보조로 둔다.
4. **실루엣/구조만 그린 뒤 첫 비교**. 축·평행선·부품 두께·연결과 투영을 먼저 잠근다. 구조 사본을 남기고, 측면·상판·받침이 빠졌다면 기능 버튼을 그리지 말고 먼저 고친다. 마감이 고정 실루엣 밖으로 나가면 구조 단계로 되돌린다.
5. 재질별 명암과 기능 연결을 그린다. 유리/도장 금속/고무에 동일한 사각 베벨 처리를 반복하지 않는다.
6. **중간 비교**. 같은 배율의 기준/이전/후보를 ×2·×3·×6·흑백으로 실제 열어 본다. 부족한 부분과 수정 위치를 적는다.
7. 국소 마감은 기능과 힘/빛의 방향에 연결한다. 큰 평면을 채우기 위한 무작위 점과 테두리 추가는 중단한다.
8. 최종 원본을 다시 열고 PNG를 재출력한다. 치수·알파·색·경계·원본 일치를 검증한다.
9. 배경/플레이어와 비교한다. 정적 예비 검토와 실제 엔진 검증을 명확히 구분한다. 배경 문제가 드러나면 환경 승인 보류 사유를 남긴다.
10. 파일별 승인 상태와 근거를 기록한다. 완료되지 않은 게이트를 숨기거나 `Generated`/`Validation` 폴더 이름으로 승인을 대신하지 않는다. 승인된 범위만 반입한다.

### 추가 제작에서 발견한 형태 실패

현미경/카트/랙 batch2 r3는 규격 검사에 통과했지만 사용자 검토에서 형태가 일그러졌다는 피드백을 받았다. 미세 명암과 연결 패치를 더하는 방식이 부품의 두께·축·원근 오류를 가렸다. 따라서 기존 r1–r3의 규격 기록을 아트 승인으로 재해석하지 않는다.

batch2 r4는 같은 캔버스에서 구조부터 다시 그렸다. 단안 현미경의 광축, 반복 선반·기둥·차축, 서버 슬롯의 좌우 정렬을 고정하고 이전/구조/최종 비교를 추가했다. 자세한 좌표와 남은 스타일 차이는 [batch2 교정 기록](../Assets/Generated/PropStyleLab/batch2/README.md)에서 관리한다. 이 교정이 상위 폴더의 기존 3종까지 자동으로 승인하는 것은 아니다.

## 7. 결과를 보는 곳

- [비교 뷰어와 제작 흐름](../Assets/Generated/PropStyleLab/review.html): 기준/블록아웃/r1/r2/r3, 동일 배율·흑백, 조립 비교. 정수 확대를 유지하며 자동 맞춤 축소를 하지 않는다.
- [실행 절차](ASEPRITE_PIPELINE.md#프랍-스타일-시험실--실행-예): 재현 명령과 덮어쓰기 방지.
- `r1`·`r2`는 보존된 이전 단계이며 `r3`가 이번 시험의 최신 후보다. 원본은 수정할 수 있지만 재생성 스크립트로 덮어쓰지 않는다.

### 검증 범위

- `test_prop_style_pipeline.ps1`: 위상 복원·무손실 역변환, 격자 밖 픽셀 거부, 투명 경계의 측정 제외, 변화량 경계값, 구형 생성기의 기본 실행 차단, 기존 원본 덮어쓰기 거부, 기존 3종 PNG 보존, 매번 새 폴더에서 r3 재생성 후 픽셀 일치. 실행 결과는 `tests/pipeline-result.json`.
- `verify_prop_style_studies.ps1`: r1/r2/r3 모두 Aseprite 재열기·레이어·프레임·PNG 재출력/규격 검사 통과. 검사기는 **아트 승인 상태를 판단하지 않는다**.
- `check_prop_review_html.cjs`: HTML 스크립트 문법, 제어 요소 ID, 로컬 문서/이미지 링크, 모든 자산/배율 조합의 이미지 존재 검사 통과. 로컬 파일의 자동 브라우저 열기는 URL 보안 정책으로 거부되어 우회하지 않았다. 브라우저 레이아웃·버튼 동작은 미검증이며 파일을 직접 열어 확인할 수 있다. 아트 판단은 별도로 열어 본 비교 PNG를 근거로 했다.

# 아트 문서 체계와 적용 순서

이 파일은 아트 관련 문서를 한 파일로 무리하게 합치지 않고, **어떤 판단을 어느 문서가 책임지는지** 정리한 색인이다. 공통 규칙은 한 곳만 단일 출처로 두고 캐릭터·몬스터·센트리처럼 맥락이 필요한 규격은 전문 문서로 유지한다.

## 빠른 시작

새 리소스를 만들 때는 다음 순서로 읽는다.

1. [`ART_GUIDE.md`](ART_GUIDE.md) **§0 승인 원화 보존**을 먼저 읽는다. 자연어 요청 → 기존 그림체로 원화 생성 → 사용자 승인 → 보존형 Aseprite 픽셀화 순서를 따른다. Native4는 현행 호환 프로파일이며 보존 손실이 크면 규격을 재검토한다.
2. 방 배경이면 [`BACKGROUND_ART_DIRECTION.md`](BACKGROUND_ART_DIRECTION.md)를 먼저 읽는다. 얕은 사이드뷰 공간, 고유색 보존, 고정 배경/상호작용 프랍 위계를 적용한다. 메탈슬러그 비교와 시안별 회귀·미채택 이유는 [`BACKGROUND_RESEARCH_LOG.md`](BACKGROUND_RESEARCH_LOG.md)에서 확인한다. 최신 이미지가 자동으로 기준본은 아니다.
   대상이 인물·특수 몬스터·센트리면 아래의 자산별 전문 문서를 추가로 확인한다.
   프랍이면 [`PROP_STYLE_REVIEW.md`](PROP_STYLE_REVIEW.md)의 기존 런타임 분석·실패 반례를 읽되, 과거 재설계 시험을 승인된 전환 방식으로 쓰지 않는다.
   애니메이션을 만들거나 수정할 때는 [`PIXEL_ANIMATION_GUIDE.md`](PIXEL_ANIMATION_GUIDE.md)에서 동작별 프레임 수·표시 속도와 현재 구현 차이를 확인한다.
3. [`ASEPRITE_PIPELINE.md`](ASEPRITE_PIPELINE.md)의 **현재 실행 경로**에서 자산별 설정과 재현 명령을 확인한다. `crisp-final-r1`의 원본색·경계 보존을 기본으로 하되, 의료실은 원본 기반 준비 단계 뒤 pixelPitch=2.0을 선택했다. 이는 전 자산의 강제값이나 게임 출력 배율이 아니다. 과거 평균 축소·대비 강화 명령을 신규 작업에 쓰지 않는다.
4. [`RESOURCE_USAGE_GUIDE.md`](RESOURCE_USAGE_GUIDE.md)에서 피벗·레이어·방 조립 방식을 확인한다.
5. 승인 원화/후보의 형태·색·재질·디테일 보존 비교를 먼저 한다. 이어 기존 게임 리소스와 현행 1×·화면 ×2·×3·×6 및 흑백/조립 비교를 한다. 새 프로파일은 별도 합의한 배율로 검수한다. 원화 승인·보존 결과 승인·규격 통과·런타임 승인을 구분하고 허용된 파일만 반입한다.
6. [`ART_ASSET_STATUS.md`](ART_ASSET_STATUS.md)에 대상 버전과 현재 선택·승인 범위를 기록한다. 실행 당시의 검사 스냅샷은 보존하고 이후 피드백은 상태 기록에 연결한다.

## 충돌 해결 순서

**최우선:** 사용자 요청과 승인 원화가 개별 자산의 디자인 기준이다. 일반 그림체 지침은 원화 생성에 적용하고, 픽셀화에서 승인 원화를 임의로 다시 설계하는 근거로 쓰지 않는다. 엔진 규격과 충돌하면 원화를 희생하거나 코드를 몰래 바꾸지 않고 손실/호환성 대안을 제시해 합의한다.

1. 특정 자산 문서에 **명시적인 수치 예외**가 있으면 그 자산에만 적용한다. 예: 센트리의 640×640 작업 캔버스와 중앙 회전축.
2. 픽셀 단위·알파·카메라·조명은 현행 `ART_GUIDE.md` 프로파일을 따르고, 신규 자산의 크기·팔레트는 §0의 보존 검토로 결정한다. **캐릭터의 8~16색 목표는 배경과 구분하기 위해 유지한다.** 배경·프랍의 일괄 색 수 상한과 실패 시험 캔버스를 절대 기준으로 적용하지 않는다.
3. 제작 방법과 명령은 `ASEPRITE_PIPELINE.md`를 따른다.
4. 엔진 배치와 레이어는 `RESOURCE_USAGE_GUIDE.md`를 따른다.
5. 문서에 없는 새 예외는 작업 파일에만 숨기지 말고 관련 전문 문서와 이 색인에 함께 기록한다.
6. 2026-09-22 배경 방향에서 정비홀 v2의 깊은 지면은 미채택, 전력실 v2의 재색칠은 불만을 남긴 현상 유지다. 이전 분석의 ‘바닥을 더 깊게’나 최신 노란 배전반을 자동 표준화하지 않는다. 기존 디오라마의 85%/70% 구도는 신규 배경의 강제 비율이 아니다.

## 유지 원칙

- 공통 규칙을 전문 문서에 복사하지 않고 `ART_GUIDE.md`의 해당 절을 링크한다.
- `.aseprite`는 편집 가능한 제작 원본, PNG/JSON은 재생성 가능한 산출물, Godot 자산은 런타임 결과로 구분한다.
- 콘셉트 원화 승인, pixelPitch 선택, 결과 외관 승인과 게임 적용 승인을 별도로 기록한다. 현재 상태는 ART_ASSET_STATUS, 당시 검사·해시는 자산별 verification.json으로 구분한다.
- 자동 규격 통과·스타일 검토·런타임 승인을 구별한다. 시험 이미지나 HTML 비교표가 있다는 사실만으로 검수 완료라고 쓰지 않는다.
- 폐기된 실험은 삭제해 맥락을 잃기보다 제목에 **폐기됨**을 표시하고 현재 기준으로 사용하지 않는다고 명시한다.
- 자산 폴더의 README와 manifest는 그 자산의 구현 기록이다. 프로젝트 전체의 아트 정책을 새로 정의하지 않는다. 현재 승인 상태를 중복 관리하지 않고 ART_ASSET_STATUS에 연결한다.

## 통합 결과

- v1.14 (2026-09-22): 배경 제작 방향과 전체 연구·결정 기록을 추가하고 ART_GUIDE의 구도·역할 분리 항목을 정합화했다. 네 시안의 공간 선호, 미채택, 톤 문제, 고유색 불만을 남긴 현상 유지를 ART_ASSET_STATUS에 구별했다. 게임 반입이나 이미지 변경은 수행하지 않았다.

- v1.13: 캐릭터 8~16색 목표와 배경·프랍의 보존형 팔레트를 구분했다. 의료실 2.0 선택 및 단위 정의, 현재 실행 경로, 단일 승인 상태 기록을 연결했다. 범용 실행기 구현과 게임 출력 프로파일 검증은 후속 항목으로 남겼다. 코드·원본·결과 이미지·런타임은 변경하지 않았다.

- 실제 픽셀 제작의 정의와 Native4 공통 규격은 `ART_GUIDE.md` §10으로 통합했다.
- v1.11에서 원화 생성/사용자 승인/보존형 픽셀화를 §0으로 통합하고, 승인 원화와의 직접 비교를 §11의 첫 검수로 추가했다. v1.12에서는 평균 축소로 인한 경계 둔화 실패와 선명도 보존 원칙을 §0에 추가했다. 원본 크기 유지 변환 도구와 세 프랍 시안을 구현했으나 새 엔진 프로파일은 미확정이다.
- Aseprite 조작·자동화·내보내기·검사·게임 반입은 `ASEPRITE_PIPELINE.md`에 모았다.
- 캐릭터·크롤러·센트리는 서로 다른 피벗과 형태 잠금값이 필요하므로 전문 문서를 유지했다.
- `RESOURCE_USAGE_GUIDE.md`의 Unity 절과 Native8 Power Relay 절은 현재 기준과 섞이지 않도록 레거시·폐기 기록으로 분리했다.

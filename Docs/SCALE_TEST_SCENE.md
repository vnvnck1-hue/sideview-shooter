# 규격 테스트 씬 — 그레이박스 치수 비교

*작성 2026-09-24 · 대상 `GodotPrototype/scenes/ScaleLab.tscn` · 상위 계획 [`SCALE_STANDARDIZATION_PLAN.md`](SCALE_STANDARDIZATION_PLAN.md) §2~3*

캐릭터를 직접 움직여 문·통로·턱·상자·층고·프랍의 **후보 치수**를 나란히 비교하는 씬이다.
[`SpaceLab`](SPACE_TEST_SCENE.md)이 넓이와 방 연결의 감각을 본다면, 이 씬은 **치수를 반복 비교**한다.
기준자는 [`SCALE_CHARACTER_BASELINE.md`](SCALE_CHARACTER_BASELINE.md)의 측정값이다.

> 여기 나오는 치수는 모두 **후보**다. 확정 규격이 아니다. 채택하면 §6에 이유와 함께 옮기고, 그 뒤에 제작 문서를 고친다.

## 1. 구성

본편과 **같은 플레이 루프**(이동·조준·사격·구르기·줌·카메라)를 쓴다. `main.gd` 를 상속하고, 방 하나만 그레이박스 데이터로 바꿔 끼운다.
방 데이터는 `RoomData.extra` 에 올리므로 본 맵·지도·`validate_map` 에는 영향이 없다. 적은 나오지 않는다.

| 파일 | 역할 |
|---|---|
| `scripts/scale_lab_data.gd` (`ScaleLabData`) | 구역·후보 배치, 캐릭터 기준자 상수, 세로 판정 규칙, 판정 함수, 탄 차단 |
| `scripts/scale_lab_view.gd` (`ScaleLabView`) | 배경 격자·충돌 지형·통과 배경·전경 가림·치수 라벨·판정 상자 그리기 |
| `scripts/scale_lab.gd` | 씬. 세로 판정·턱 오르기·탄 차단·키 입력·HUD·카메라 세로 중심 |
| `scripts/scale_lab_feet.gd` | 이동 **뒤** 발 높이를 맞추는 보조 노드 (플레이어 다음, 카메라 전) |
| `tools/validate_scale_lab.gd` | 실측 툴. 결과는 [`SCALE_TEST_RESULTS.md`](SCALE_TEST_RESULTS.md) |
| `tools/scale_lab_shot.gd` | 구역·후보별 스크린샷 |

방은 9행(천장 여유 1054) 그레이박스 구간 뒤에 실제 workshop 타일 열을 이어 붙였다. 전체 폭은 약 49,000px다.
그레이박스 구간의 타일은 무지 배경으로 덮는다. **B** 로 덮개를 끄면 같은 자리의 실제 타일과 대조할 수 있다.

## 2. 조작

본편 조작에 아래 키를 더했다.

| 키 | 동작 |
|---|---|
| `[` `]` | 이전·다음 구역 |
| `,` `.` | 이전·다음 후보 앞으로 이동 (막힌 칸 사이를 건너갈 때) |
| `G` (`Shift+G` 역순) | 세로 판정 규칙 순환 (§3) |
| `T` (`Shift+T` 역순) | 턱 오르기 한계 순환: 0 · 32 · 64 · 96 |
| `N` | 충돌 끄기 — 모든 지형을 통과해 자유롭게 걷는다 |
| `H` | 라벨: 전체 → 간단 → 끄기 |
| `B` | 그레이박스 배경 ↔ 실제 타일 |
| `F3` | 줌 (본편과 같은 ×2 · ×3 · ×4) |

화면 좌상단 HUD는 다섯 줄이다.

1. 구역
2. 규칙
3. 지금 상태: 자세·몸 높이·발 높이·머리 위 여유·x
4. 카메라 조건
5. 가장 가까운 후보의 판정

## 3. 새로 넣은 판정 — 본편에는 없다

기준표 §3대로 본편에는 "통로가 낮아서 못 지나간다"는 판정이 없다. 이 씬에서만 아래 규칙을 켠다. **어느 방식을 본편에 들일지는 아직 정하지 않았다.**

### 세로 판정 (G)

| 규칙 | 서기 | 웅크림 | 구르기 | 뜻 |
|---|---|---|---|---|
| **외형 기준** (기본) | 270 | 207 | 179 (전 구간) | 그림이 실제로 차지하는 높이 |
| 외형 + 아이들 여유 | 291 | 207 | 179 (진행 20~80%만, 시작·끝 263) | 아이들 스쿼시 상한까지 보고, 구르기 프레임 변화까지 따른다 |
| 판정 상자 기준 (관대) | 250 | 190 | 150 | 그림보다 작은 판정. 후드 끝이 인방에 살짝 겹쳐도 지나간다 |

- 몸 높이가 앞 지형의 여유보다 크면 판정 상자 가장자리에서 멈춘다.
- 이미 낮은 천장 아래에 있고 서 있을 수 없으면 웅크린 자세가 강제된다. 본편 조작은 웅크린 동안 걸을 수 없으므로 **빠져나가는 길은 구르기뿐**이다.
- 웅크린 자세도 들어가지 않는 높이(여유 < 웅크림 높이)에서는 "끼임" 상태가 된다. 구르기로만 빠져나간다.
- 좌우 판정 폭은 124(±62)로 두었다. 피격 상자와 같은 폭이고, 서 있는 몸통 폭 168보다 좁다.

### 턱 오르기 (T)

- 단차가 한계 이하이면 걸어서 바로 올라선다. 한계를 넘으면 벽이다.
- 내려서기는 언제나 된다. 떨어지는 모양만 있고 낙하 판정은 없다.
- 한계 0은 점프와 계단이 없는 현재 규칙에 해당한다. 모든 턱이 벽이 된다.

### 탄 차단

회색 지형은 탄을 막는다. 본편의 벽 클리핑(`RoomSolid`)보다 먼저 적용된다. 파랑·주황·보라는 탄을 막지 않는다.

### 문·통로 (외형 기준 규칙)

- **서서 통과 하한은 여유 270 이상이다.** D288(+18)까지 서서 지나가고, D256부터는 구르기로만 지나간다.
- 아이들 여유 규칙에서는 D288도 구르기로 바뀐다(291 > 288). 문 높이를 288로 잡으면 규칙 선택에 따라 결과가 갈리는 경계값이 된다.
- 관대 규칙에서는 D256과 T256×384도 서서 지나간다.
- 한 번 구르기로 통째로 빠져나가는 통로 길이 한계(이론값)는 외형·관대 기준 **306**, 아이들 여유 기준 **226**이다. 그보다 긴 통로는 이어 구르기가 필요하다.
  - 여유 ≥ 207이면 통로 안에서 웅크려 버틸 수 있다.
  - 여유 207 미만(T192)이면 안에서 끼인다.
- T160은 구르기(179)로도 들어가지 못한다. 관대 규칙(150)에서만 지나간다.

### 턱·계단

- 턱 오르기 한계와 결과가 정확히 일치한다. 한계 32는 S16·S32·단 32 계단을, 한계 64는 S48·S64·단 64 계단을 오른다.
- 상자 C64도 한계 64에서는 **걸어 넘는 발판**이 된다. 엄폐물로 쓸 상자는 오르기 한계보다 높아야 한다.

### 엄폐 상자 (수평 사격)

| 상자 | 서서 쏘면 | 웅크려 쏘면 | 웅크린 몸 가림 |
|---|---|---|---|
| C64 | 넘김 | 넘김 | 30% |
| C96 · C128 | 넘김 | 막힘 | 46% · 61% |
| C160 이상 | 막힘 | 막힘 | 77% ~ |

"서면 넘겨 쏘고 웅크리면 가려지는" 구간은 **94 < 높이 < 160** 이다. 이 씬의 C96·C128이 여기에 들어간다.
단, 웅크린 몸(207)을 절반 넘게 가리려면 높이가 104 이상이어야 한다. 그래서 이 구간의 실용 후보는 **C128 전후**로 좁혀진다.

## 6. 판단 기록 — 플레이하며 채운다

자동 실측이 알려 주는 것은 "지나갈 수 있는가"뿐이다. 편한지, 답답한지, 잘 읽히는지는 직접 플레이해서 적는다.
한 번에 기준을 하나만 바꾸고, 줌 ×3·카메라 표준을 기본 조건으로 둔다.

| 날짜 | 조건 (규칙 · 턱 · 줌) | 후보 | 소감 | 채택·보류 | 이유 |
|---|---|---|---|---|---|
| | | | | | |

**미결정 — 규격 초안(계획 §4) 전에 정할 것**

1. 세로 판정을 본편에 들일지 여부와 규칙 (외형 / 아이들 여유 / 관대)
2. 웅크린 채 걷기를 넣을지. 지금은 낮은 통로를 구르기로만 지날 수 있다.
3. 턱 오르기 한계 (0 / 32 / 64). 한계를 정하면 엄폐 상자의 최소 높이도 따라 정해진다.
4. 정면문·가구 아트를 규격에 맞춰 다시 그릴 범위

## 7. 다시 돌리기

```bash
# 실측 (헤드리스) → Docs/SCALE_TEST_RESULTS.md 갱신
godot --path GodotPrototype --headless --fixed-fps 60 --script res://tools/validate_scale_lab.gd
# 스크린샷 (창) → user://shots/scale_lab_*.png
godot --path GodotPrototype --script res://tools/scale_lab_shot.gd -- 40 0
```

후보를 더하거나 바꾸려면 `scale_lab_data.gd` 의 해당 `_zone_*` 함수에서 목록만 고친다. 배치 간격과 라벨, 실측 대상은 자동으로 따라온다.

## 1. 버스 구조

버스는 `.tres` 없이 `audio_manager.gd` 가 코드로 만든다. 에디터 설정과 어긋날 일이 없고, 믹스 값이 전부 한 파일에 모인다.

```
Master  -1 dB   ← HardLimiter (ceiling -1.5 dB, release 0.035 s)
├─ SFX      -3 dB
│  └─ Weapon  -1 dB   ← LowPass 9.5 kHz → Delay(슬랩백) → Reverb  ※ 2.5장
├─ Ambience -10 dB    ← LowPass 2.2 kHz → Compressor(사이드체인 = Weapon)  ※ 2.6장
├─ UI       -9 dB
└─ Voice    -13 dB    ← NPC 대사 블립 (글자마다 하나)  ※ 2.8장
```

- **Weapon 이 SFX 를 거쳐 나간다.** SFX 페이더 하나로 효과음 전체를 잡을 수 있고, 무기만 따로 더 누를 수도 있다.
- **Master 하드 리미터**는 마지막 안전망이다. 연사 + 탄착 + 탄피가 한꺼번에 몰려도 클리핑하지 않는다.
- **Voice 를 따로 둔 이유**: 대사 블립은 한 줄에 서른 번 울린다. SFX 에 섞어 두면 총소리를 키울 때
  말소리까지 같이 커진다. 대화의 볼륨은 대화만 보고 잡아야 한다.
- 볼륨 조절 API: `Audio.set_category_volume("SFX", 0.6)` (설정 메뉴용), `Audio.set_enabled(false)` (전체 음소거).

## 0. 말소리는 따로 본다

NPC 대사 블립은 이 문서의 나머지와 출처가 다르다 — 받아 온 샘플이 아니라
`Tools/build_npc_voice_blips.py` 가 **합성한** 것이고(저작권 없음), 규칙도 다르다.
자세한 것은 `Docs/DIALOGUE_SYSTEM.md` §3-2. 여기서 알아 둘 것은 셋뿐이다.

- 버스 `Voice` -13 dB, 전용 풀 4보이스(`POOL_VOICE`) + 웅얼거림 전용 재생기 하나. 공용 flat 풀을 쓰면 한 줄 찍는 동안 UI 소리가 낄 자리가 없다
- 파일 55개는 `SOUNDS` 에 없다 — 경로가 `sfx/voice/<말투>_<모음>.wav` 규칙이라 표로 늘어놓는 것보다 만들어 쓰는 쪽이 정확하다(`VOICE_DB` 만 표로 둔다)
- 음높이는 `audio_manager` 가 흔들지 않는다 — 인물·억양·글자별 흔들림을 호출부가 정해 넘긴다
- 동시 보이스 집계(`_allowed`/`_mark`)를 타지 않는다. 밀어내기로 가로챈 보이스는 `finished` 가 오지 않아 집계가 한쪽으로만 쌓인다

## 2. 귀에 거슬리지 않게 하려고 건 장치 4가지

프로토타입 사운드가 거슬리는 원인은 거의 정해져 있다. 각각에 대응하는 장치를 넣었다.

### ① 같은 파일이 같은 높이로 반복된다
모든 재생에 **피치와 음량을 무작위로 흔든다**(`pitch`, `db_var`).
특히 발소리는 채택 샘플이 `footstep_01.ogg` 하나뿐이라 이 장치에 전적으로 의존한다 — 피치 0.86~1.08, 음량 ±2.5 dB.

### ② 연사 때 소리가 뭉치고 저역이 쌓인다
소리마다 **최소 간격(`gap`)**과 **동시 보이스 수(`voices`)** 제한이 있다.
발사는 초당 11발이라 이게 없으면 저역이 그대로 누적돼 먹먹해진다.

- `fire_low` 의 `gap = 0.16` 은 의도된 값이다. 초당 11발 중 **두 발에 한 번만** 보디 레이어가 깔려서, 무게는 생기되 저역은 쌓이지 않는다.
- 보이스 풀(20개)이 꽉 차면 새 소리를 **조용히 버린다**. 억지로 끼워 넣는 것보다 낫다.

**잔향은 특히 위험하다.** `fire_tail_01` 은 0.61초짜리다. 이걸 매 발 깔면 초당 11번 × 0.61초가
통째로 겹쳐 순식간에 진창이 된다. 그래서 잔향만은 `gap` 이 아니라 **재생 조건 자체를 다르게** 걸었다 —
`_fire_tail_done` 플래그로 "사격이 끊겼을 때 한 번"만 울린다(`audio_manager.gd:_process()`).

### ③ 고역이 쏘아붙인다
버스 단위 로우패스로 깎았다.

- **Weapon 6.5 kHz** — 금속 타격의 쇳소리가 초당 11번 반복되면 금세 피로해진다.
- **Ambience 700 Hz** — 원본이 우주선 엔진이라 고역에 금속성 휘파람이 있다. 통째로 잘라 "지하 공간의 울림"만 남겼다.

### ④ 패닝이 과하다
사이드뷰에서 하드 패닝은 금방 피곤해진다. `panning_strength = 0.35` 로 낮게 잡았다.

## 2.5 총성의 공간감 — 방이 소리에 개입한다

총소리가 납작하게 들리는 원인은 샘플이 아니었다. **방이 소리에 전혀 개입하지 않는 것**이었다.
폭 640px 통로(`corr_mid`)와 4096px 격납고(`hangar`)에서 완전히 같은 소리가 났다. 6.4배 차이나는
공간에서 음향이 동일하면, 아무리 좋은 샘플이어도 "공간에서 총을 쐈다"가 아니라 "녹음을 튼다"로 들린다.

그래서 Weapon 버스에 두 가지를 걸고, **방 크기로 그 값을 실시간으로 바꾼다**(`_apply_room_space`).

```
Weapon  ← LowPass 6.5kHz → Delay(슬랩백 ×2) → Reverb
                              ↑ 방 폭이 정함    ↑ 방 폭이 정함
```

순서가 중요하다. 고역을 먼저 깎고 → 그 결과를 벽에 튕기고 → 남은 것이 잔향이 된다.
반대로 걸면 반사음만 쨍하게 남아 오히려 더 납작해진다.

### ① 슬랩백(Delay) — 공간의 **크기**를 말한다

반대쪽 벽을 때리고 돌아오는 첫 반사다. 리버브보다 이쪽이 크기를 훨씬 명확하게 전달한다.
**탭 두 개를 좌우로 갈라 패닝**(+0.42 / −0.36)해서 스테레오 폭도 같이 만든다.
사이드뷰라 패닝을 0.35로 낮게 잡아 둔 탓에 플레이어 총이 항상 정중앙 모노였는데, 이게 그걸 푼다.

시간은 물리로 계산한다 — `CELL(128px) ≈ 1m` 로 잡으면 천장 4~9칸 = 4~9m, 격납고 32m 로
지하 산업시설 치수가 나온다. 왕복 시간 = 폭(m) / 343(m/s).

두 번째 탭은 1.68배 — **정수배를 피해야** 통 속처럼 울리지 않는다.
피드백은 끈다. 초당 11발에서 피드백은 순식간에 쌓인다.

### ② 리버브 — 공간의 **재질**을 말한다

콘크리트·금속 벽에 남는 잔향. `hipass 0.34` 로 **저역은 리버브에 넣지 않는다** —
`fire_sub` 까지 잔향에 들어가면 연사에서 바로 진창이 된다. 직접음(`dry 1.0`)은 손대지 않는다.

### 방별로 실제 걸리는 값

| 방 | 폭 | 환산 | 슬랩 1·2 | 슬랩 레벨 | room_size | wet | tail 보정 |
|---|---:|---:|---|---:|---:|---:|---:|
| `corr_mid` | 640px | 5m | 15 / 25ms | -17dB | 0.30 | 0.10 | -5.0dB |
| `generator` | 1152px | 9m | 26 / 44ms | -16.1dB | 0.39 | 0.13 | -3.8dB |
| `workshop` | 1792px | 14m | 41 / 69ms | -15.0dB | 0.51 | 0.17 | -2.3dB |
| `mess_hall` | 2304px | 18m | 53 / 88ms | -14.1dB | 0.60 | 0.20 | -1.1dB |
| `hall` | 3072px | 24m | 70 / 118ms | -12.8dB | 0.74 | 0.24 | +0.6dB |
| `hangar` | 4096px | 32m | 93 / 157ms | -11.0dB | 0.92 | 0.30 | +3.0dB |

`fire_tail` 도 방 크기를 따라간다. 통로에서는 5dB 죽이고 격납고에서는 3dB 살린다 —
좁은 데서 잔향이 크면 어색하고, 넓은 데서 작으면 공간이 죽는다.

### 앰비언스 베드와 규칙이 다르다

베드는 **같은 구역이면 방을 옮겨도 갈지 않는다**(공간이 한 번씩 흔들려서). 공간감은 반대로
**방을 옮길 때마다 매번 갱신한다.** 같은 정비 구역이어도 통로(640px)와 격납고(4096px)는
크기가 6배 차이 나고, 그 차이가 곧 공간감이기 때문이다.

### 덤 — 센트리건이 저절로 멀어진다

리버브·슬랩은 버스에 걸려 있어 거리와 무관하게 일정한데, 직접음은 `AudioStreamPlayer2D` 의
거리 감쇠를 받는다. 즉 **멀리 있는 센트리건일수록 직접음 대비 잔향 비율이 자동으로 올라간다.**
따로 계산하지 않아도 거리감이 생긴다.

## 2.6 총격음을 크고 강하게 — 네 갈래로 나눠 손봤다

"약하다"는 신호에 볼륨만 올리면 다 같이 커질 뿐 타격감은 그대로다. 원인을 넷으로 나눴다.

### ① 애초에 너무 작았다

발사음 본체가 **-20 dBFS** 로 나가고 있었다. 버스 감쇠가 -10 dB(Weapon -6 → SFX -3 → Master -1)나
쌓여 있었고 파일 피크도 -3 dBFS 였다. Weapon 버스를 -1 로 올리고, 파일을 -1 dBFS 로 다시 뽑고,
레이어별 db 도 올려 **전 레이어가 +10~12 dB** 올라갔다.

| 레이어 | 이전 실효 | 이후 실효 | 변화 |
|---|---:|---:|---:|
| `fire_body` | -20.0 dB | -10.0 dB | +10.0 |
| `fire_attack` | -28.0 dB | -17.0 dB | +11.0 |
| `fire_sub` | -26.0 dB | -14.0 dB | +12.0 |
| `fire_tail` | -30.0 dB | -18.0 dB | +12.0 |
| `turret_fire` | -24.0 dB | -12.0 dB | +12.0 |

3레이어가 동시에 터지는 최악의 순간이 -3.6 dBFS — 마스터 리미터(-1.5)가 받아낸다.

### ② 리미터가 펀치를 먹고 있었다

**이게 가장 컸다.** 마스터 하드리미터의 release 가 0.12초였는데 **발사 간격이 0.09초다.**
릴리스가 발사 간격보다 길면 연사를 시작한 순간부터 리미터가 한 번도 회복하지 못하고
계속 눌린 상태로 남는다. 그리고 리미터가 깎는 것은 정확히 **타격감을 만드는 어택 피크**다.

볼륨을 아무리 올려도 펀치만 사라지는, 원인 찾기 고약한 종류의 먹먹함이었다.
`release = 0.035` 로 내려 발사와 발사 사이에 반드시 원래대로 돌아오게 했다.

### ③ 로우패스가 어택을 깎고 있었다

Weapon 6.5 kHz 는 발사음 본체가 Kenney 금속 타격이던 시절의 값이다. 그 쇳소리가 초당 11번
반복되는 걸 막으려던 것이고 그때는 맞았다. 실총 녹음이 본체가 되고 금속이 -11 dB 보조로
내려간 지금은 6.5 kHz 가 **"탁"을 깎아먹는 쪽**이라 9.5 kHz 로 올렸다.

### ④ 파일 자체에 어택 대비가 없었다

타격감은 절대 음량이 아니라 **대비**에서 온다. 그래서 스테이징 단계에서 트랜지언트를 세웠다
(`stage_gunshot_audio.py` 의 `punch_db` / `punch_ms`). 어택 구간을 밀어올린 뒤 전체를 다시
정규화하면 피크는 그대로인데 몸통이 상대적으로 내려앉아 어택이 튀어나온다.

창을 파일 맨 앞에 고정하면 안 된다 — 피크가 오는 시점이 샘플마다 다르다(gunshort03 은 4 ms,
gunshort12 는 21 ms). 고정 창을 쓰면 피크가 늦은 쪽에서는 어택 앞의 조용한 부분만 키우고 끝나
**대비가 오히려 뒤집힌다.** 그래서 피크 위치를 찾아 거기까지 밀고, 이후로 지수 감쇠시킨다.

| 파일 | 앞 30 ms 대비 몸통 |
|---|---:|
| `fire_body_01` | +11.4 dB |
| `fire_body_02` | +4.0 dB |
| `turret_fire_01` | +1.1 dB |

그리고 **저역을 매 발 깔도록 바꿨다.** 예전에는 `gap 0.16` 으로 두 발에 한 번만 깔았다 —
원본이 220 ms 였을 때는 맞는 판단이었다. 150 ms 로 줄이고 어택을 세운 지금은 매 발 깔아도
쌓이지 않고, **한 발 걸러 오는 무게는 타격감이 아니라 박자로 들린다.**

### ⑤ 덤 — 쏘는 동안 방이 비켜 준다

체감 음량은 절대값이 아니라 주변과의 차이로 정해진다. Ambience 버스에 컴프레서를 걸고
**Weapon 을 사이드체인 키로** 삼았다(`_add_ambience_duck`). 쏘는 순간 방 소리가 움찔 물러나고,
끝나면 420 ms 에 걸쳐 천천히 돌아오면서 "방금 시끄러웠다"는 여운이 남는다.

Weapon 은 SFX 를 거쳐 나가므로 이 컴프레서를 통과하지 않는다 — **총소리 자체는 전혀 눌리지 않는다.**

## 2.7 확정 프리셋 (2026-09-20)

프리셋 11개를 게임과 같은 조건으로 합성해 비교한 뒤 둘을 골랐다.
비교 페이지는 `python Tools/build_gunshot_presets.py` 로 다시 만들 수 있다.

### 플레이어 — "두껍게" (p2)

발사음이 **4레이어**가 됐다.

| 키 | 소스 | 레벨 | 역할 |
|---|---|---:|---|
| `fire_body` | gunshort03 / gunshort12 | -5 dB | 본체. 배리에이션 2종 중 하나가 매 발 |
| `fire_body2` | gunshort10 | -9 dB | **두께 층 — 7ms 늦게, 피치를 내려 깔린다** |
| `fire_attack` | Kenney 금속 | -13 dB | 이 팩에 없는 "탁"만 얇게 |
| `fire_sub` | mg04 | -7 dB | 저역. 매 발 |

핵심은 `fire_body2` 다. 같은 순간이 아니라 **7ms 늦게** 깔리기 때문에 한 발이
하나의 점이 아니라 짧은 덩어리가 된다. 피치를 보디보다 낮게(0.87~0.93) 잡아야
"같은 소리가 두 번 났다"로 안 들린다.

그 7ms 지연은 **파일 앞에 무음으로 구워 넣었다.** Godot 의 `AudioStreamPlayer` 에는
시작 지연이 없어서 타이머를 돌리지 않는 한 다른 방법이 없다. 소리 하나 늦추자고
타이머를 붙이는 것보다 파일에 굽는 쪽이 정확하고 싸다.

### 센트리건 — "2연장 교대" (t2)

`sentry_turret.gd` 는 **포신 2개가 0.055초 간격으로 번갈아** 쏜다. 그런데 소리는 한 장뿐이라
초당 18발이 그냥 기계적인 연속음으로 들렸다. 그 구조를 소리로 만들었다.

| 키 | 소스 | 레벨 | 역할 |
|---|---|---:|---|
| `turret_fire_a` | gunshort06 (우 0.30) | -6 dB | 포신 A |
| `turret_fire_b` | gunshort08 (좌 0.30) | -3.5 dB | 포신 B |
| `turret_crack` | gunsound03 40ms | -13 dB | 매 발 얹는 고역 크랙 |

세 가지가 함께 작동해야 효과가 난다.

1. **교대** — `turret_fire()` 가 A/B 를 번갈아 울린다. 0.30초 이상 쉬었다 다시 쏘면
   항상 A 부터 — 첫 발이 매번 같아야 사격 시작이 또렷하다.
2. **좌우 분리는 파일에 구워져 있다** — `AudioStreamPlayer2D` 의 위치 패닝으로는 안 된다.
   두 포신 간격이 몇백 px 인데 가시 폭이 4480 px 라 화면 비율상 거의 0 이다.
   그래서 스테레오로 ±0.30 을 구워 냈다.
3. **크랙** — 저역뿐이던 센트리건에 "탕" 하는 지점을 만든다. 40ms 라 18발/초에도 안 쌓인다.

### `turret_fire_b` 의 -3.5 dB 는 취향이 아니라 계산값이다

포신 A(-6.0)보다 2.5 dB 높다. 두 파일 다 -1 dBFS 로 정규화했는데도 샘플마다 피크 대비
에너지가 달라서, 그냥 두면 **좌우가 2.5 dB 어긋난다.** 그러면 "두 문이 교대로 때린다"가
아니라 "한쪽이 크다"로 들린다.

`stage_gunshot_audio.py` 가 실행할 때마다 이 보정값을 다시 계산해 찍어 준다.
포신 샘플을 바꾸면 그 값을 `turret_fire_b` 의 `db` 에 반영할 것.

## 5. 믹스를 조정할 때

`audio_manager.gd` 의 **`MIX` 와 `SOUNDS` 의 `db` 값만** 만지면 된다. 호출부는 건드릴 필요 없다.

- 전체가 크다 → `MIX[BUS_MASTER]`
- 총소리만 크다 → `MIX[BUS_WEAPON]`
- 한 발이 두 번 난 것처럼 들린다 → `SOUNDS["fire_body2"]["pitch"]` 를 더 내리거나 `db` 를 내린다
- 센트리건 좌우가 한쪽으로 쏠린다 → `stage_gunshot_audio.py` 를 돌려 보정값을 다시 받고 `turret_fire_b` 의 `db` 에 반영한다
- 센트리건 크랙이 거슬린다 → `SOUNDS["turret_crack"]["db"]` 를 내린다. 빼려면 `-80`
- 연사가 먹먹하고 펀치가 없다 → **먼저 마스터 리미터 `release` 를 본다.** 발사 간격(0.09초)보다 길면 원인은 거기다
- 저역이 뭉갠다 → `SOUNDS["fire_sub"]["gap"]` 을 0.16 으로 되돌린다 (두 발에 한 번만 깔린다)
- 어택을 더 세우고 싶다 → `stage_gunshot_audio.py` 의 `punch_db` 를 올리고 다시 스테이징한다. 볼륨을 올리는 것과 다르다
- 쏠 때 앰비언스가 펌핑으로 들린다 → `_add_ambience_duck` 의 `release_ms` 를 늘린다
- 발소리가 잦아 거슬린다 → `SOUNDS["footstep"]["gap"]` 을 올리거나 `db` 를 내린다
- 연사가 먹먹하다 → `SOUNDS["fire_sub"]["gap"]` 을 올린다 (저역 레이어가 덜 깔린다)
- 총이 너무 "쇳소리"다 → `SOUNDS["fire_attack"]["db"]` 를 내린다. `-80` 으로 내리면 Kenney 어택이 완전히 빠지고 실총 녹음만 남는다
- 방이 너무 울린다 → `SPACE_WET` 를 내린다 (잔향 전체). `SOUNDS["fire_tail"]["db"]` 는 마지막 한 방만 줄인다
- 방 크기 차이가 잘 안 느껴진다 → `SPACE_SLAP_DB` 의 폭을 벌린다. wet 보다 슬랩백이 크기를 더 잘 전달한다
- 총소리가 통 안에서 나는 것 같다 → `SLAP2_RATIO` 를 정수(2.0)에서 더 멀리 띄운다
- 연사할 때 저역이 뭉갠다 → `SPACE_HIPASS` 를 올려 리버브에서 저역을 더 뺀다
- 센트리건이 플레이어 총과 구분이 안 된다 → `SOUNDS["turret_fire"]["pitch"]` 를 더 내린다
- 앰비언스가 신경 쓰인다 → `MIX[BUS_AMB]` 를 내리거나 `LOWPASS[BUS_AMB]` 를 더 낮춘다

## 6. 미검증 항목

Godot 은 이 PC 에 정상 설치되어 있다(4.7). 다만 **내가 직접 띄워 들어본 것은 아니다** —
코드 리뷰와 산출물 측정까지만 했다. 아래는 귀로만 확인되는 항목이라 직접 봐 줘야 한다.

> **새 오디오 파일을 추가한 직후라면** 에디터가 한 번 다시 스캔해야 `.import` 가 생긴다.
> 에디터 창을 클릭해 포커스를 주면 자동으로 스캔하고, 아니면 `run.bat` 이 헤드리스 임포트를 먼저 돌린다.
> 스캔 전에 실행하면 `오디오 파일 없음` 경고가 뜨고 그 소리만 조용히 빠진다.

1. 자동 로드 `Audio` 가 파싱 오류 없이 올라오는지
2. 발사·발소리·탄착이 실제로 들리는지 (`assets/audio/` 가 임포트되어야 한다 — 첫 실행 시 Godot 이 자동으로 한다)
3. 방을 옮길 때 앰비언스가 끊기지 않고 크로스페이드되는지
4. 연사를 길게 눌렀을 때 먹먹해지거나 찢어지지 않는지 — 이게 제일 중요하다
